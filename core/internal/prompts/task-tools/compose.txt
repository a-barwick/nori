Run several tool calls as one script when a step needs to combine or filter many results, such as reading every calendar or every message in a list. script is JSON: {"version": 1, "concurrency": 4, "steps": [{"id": "cals", "tool": "calendar_list_calendars", "args": {}}, {"id": "events", "tool": "calendar_events", "for_each": "$cals.calendars", "as": "cal", "where": {"path": "$cal.selected", "equals": true}, "args": {"calendar_id": "$cal.id", "time_min": "2026-11-09T00:00:00Z"}}], "output": {"titles": "$events[*].events[*].summary|flatten"}}. A string that is exactly "$step.path" is replaced by that value; "{{ $step.path }}" is replaced inside text; "$$" writes a literal $. Paths use .field, [0] and [*]; end with |flatten, |count, |unique, |first or |last. A step can refer only to earlier steps and its own "as" item. Steps run in order; a for_each step's calls run in parallel, at most concurrency (up to 8) at a time; at most 32 steps and 64 calls. You can call the user's app tools and the runtime read tools, not task-control tools. Each call is checked and approved exactly as if you called it directly: a call that needs the user's approval stops the script, and after the approval you can run it again. Cite the compose result's operation_id as evidence; each call's own operation_id is listed in calls.
