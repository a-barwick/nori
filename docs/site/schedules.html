Triggers

TriggerFires
OnceAt a specific instant. A later time zone change does not move it.
RecurringBy a local start time, an IANA time zone and a recurrence rule. A repeated DST local hour runs once; a skipped hour advances to the next valid time.
WatchWhen a typed condition on a source changes, bounded by its cadence policy.

POST /v1/automations/preview previews upcoming fire times, standing access and missed-run handling before an automation is saved.

Exactly one occurrence per slot

An occurrence ID is derived deterministically from the automation ID, scheduled slot and schedule generation, so a duplicate wake or second scheduler pass finds the existing occurrence instead of starting a second task. Editing or cancelling an automation advances its generation; unstarted slots from the previous generation never run. Missed slots are explicitly recorded as skipped or expired with a reason rather than vanishing.

After every pass and edit, the scheduler stores the exact next due wake_at timestamp in nori_user_wakes with no delay cap, emitting NOTIFY nori_wake when due immediately. The 60-second repair sweep and resume pass recover any missed wake.

In-app inbox delivery

Running a task and delivering its result are recorded separately. Deliveries target the built-in in_app destination, which creates one deduplicated inbox item under /v1/inbox linking to the task and its results. Users acknowledge items via POST /v1/inbox/{id}/actions.

External Web Push and SMTP email delivery channels are not part of Nori; any non-inbox destination fails visibly with destination_missing so the host app or another host can own external notifications cleanly.

Goals

A goal (/v1/goals) tracks a longer-running outcome with completion criteria, progress notes, blockers and next actions, linked to the tasks and automations working toward it. A failed run leaves the goal intact; completing a goal stops its attached automations unless the user chooses to keep them.
