Triggers

TriggerFires
OnceAt an instant. A later time zone change does not move it.
RecurringBy a local start time, an IANA time zone and a repeat rule. A repeated local hour runs once; a skipped hour moves to the next valid time.
Event-relativeAn offset from a calendar event, following the event when it moves or is cancelled.

The editor previews the next runs, the standing access the automation will have and what happens to missed runs before anything is saved.

Exactly one occurrence per slot

An occurrence's id comes from the automation, the slot and the schedule's generation, so a second scheduler pass or a duplicate wake finds the existing occurrence instead of starting another task. Editing or cancelling an automation advances its generation; slots from the old generation that had not started never run. Missed slots are recorded as skipped or expired with a reason rather than disappearing.

After every pass and every edit, the scheduler arms a wake for the next due time: a named Cloud Tasks task or a chain of SQS delays. The resume pass repairs a wake that was lost. On a local stack the core loop checks every two seconds instead.

Delivery

Running a task and delivering its result are recorded separately. A delivery is pending, attempting, accepted, delivered, failed or uncertain; "accepted" means the channel took it, not that the user saw it. Quiet hours delay a delivery; they do not cancel the work.

Push and email delivery need provider credentials that are not configured; those destinations record a failed delivery with the reason.

Goals

A goal is an outcome the user adopted, with completion criteria, progress, blockers and next actions, linked to the tasks and automations working on it. A failed attempt leaves the goal in place; completing it stops its monitors unless the user keeps them.
