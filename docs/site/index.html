Nori

Nori is the persistent, multi-user assistant engine inside a host app. One conversation per user stays open while durable background tasks run.

Uservia host app
↕ messages down, replies up
Outer loopReplies, routes and reports results.
↕ commands down, events up
Inner loopsOne per task, such as pulling the Q3 summary or drafting the launch brief.
↓ records, leases and wakes
RuntimeSaves records, leases and wakes in Postgres. Checks budgets and approvals.
PartWhat it does
Outer loopKeeps one persistent thread per user, replies immediately, guards dispatches against prompt injection, manages explicit memory and routes work without blocking.
Inner loopsEach task runs on the Postgres-native runner with its own instructions, checkpointed state and budget. One task can wait for approval or fail without affecting the others. A subtask shares its parent's budget and stops with it.
RuntimeModels propose actions. The runtime validates them, enforces permissions and action-digest approvals, saves records in Postgres and passes recorded outcomes back to the outer loop.

Where it stands

  • One persistent thread per user, concurrent Postgres-native durable tasks (task.Runner), steering, Stop, spending budgets, durable questions and action-digest-bound approvals are built.
  • Tools connect through built-in runtime capabilities (web search, saved results, memory, uploaded images) and the MCP tool bus & provider-agnostic connections port.
  • Automations and goals run scheduled work and deliver results to the in-app inbox.
  • Results, uploads, subtasks, memories and summaries persist in Postgres and S3 (or local disk). The SSE event stream resumes after reconnects.
  • Web, iOS and macOS clients talk to the same user-scoped API (api/openapi.yaml) and resumable SSE streams.
