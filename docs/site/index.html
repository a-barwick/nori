Nori

Nori is a personal assistant. One long conversation stays open while background tasks run.

Commands go from the outer loop to tasks. Events return to the outer loop.

The outer loop handles the conversation

It replies, starts tasks, passes on corrections and proposes memory changes. Replies don't wait on task work.

Inner loops run tasks

Each task gets its own loop and instructions. One can wait or fail without affecting the others, except that a subtask shares its parent's budget and stops with it.

The runtime checks and records

Models return proposed actions. The runtime saves and validates them, and passes recorded outcomes to the outer loop.

An example conversation

Check Saturday's weather in Tucson. Also find a time for dinner.

On it. I've started both.

After seven, please.

That goes to the dinner task only. The weather task's instructions don't change.

Saturday in Tucson looks sunny, around 82°F.

The result arrives without another message from the user. Follow this message through the system.

Where it stands

  • Chat, independent tasks, steering, Stop, budgets and durable questions are built. Tasks use a persistent computer with shell and browser.
  • Tools cover search, long shell jobs, images and calendar reads. Calendar changes and email sends ask for exact approval.
  • Saved results, uploads, the event stream, subtasks, saved memories and conversation summaries, calendar offers and schedules and monitors are built.
  • Native clients and push remain planned. The roadmap separates built work from remaining gaps.
