Nori

Nori is the persistent, multi-user assistant engine inside a host app. One conversation per user stays open while durable background tasks run.

Commands go from the outer loop to tasks. Events return to the outer loop.

The outer loop handles the conversation

One persistent thread per user replies immediately, guards dispatches against prompt injection, manages explicit memory and routes work without blocking.

Inner loops run durable tasks

Each task runs on the Postgres-native runner with its own instructions, checkpointed state and budget. One can wait for approval or fail without affecting the others, except that a subtask shares its parent's budget and stops with it.

The runtime checks and records

Models propose actions. The runtime validates them, enforces permissions and action-digest approvals, persists records in Postgres and passes recorded outcomes back to the outer loop.

Where it stands

  • One persistent thread per user, concurrent Postgres-native durable tasks (task.Runner), steering, Stop, spending budgets, durable questions and action-digest-bound approvals are built.
  • Tools connect through built-in runtime capabilities (web search, saved results, memory, uploaded images) and the MCP tool bus & provider-agnostic connections port.
  • Automations and goals run scheduled work and deliver results to the in-app inbox.
  • Results, uploads, subtasks, memories and summaries persist in Postgres and S3 (or local disk). The SSE event stream resumes after reconnects.
  • Web, iOS, and Mac clients connect through authenticated per-user BFF routes and resumable SSE streams.
