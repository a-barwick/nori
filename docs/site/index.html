How Nori works

Nori is a personal assistant. One long conversation stays open while background tasks run.

The outer loop handles the conversation

It replies to the user, starts tasks and passes on corrections. It only has task tools, so replies don't wait on task work.

Inner loops run tasks

Each task gets its own loop with its own instructions and budget. One can wait or fail without affecting the others.

The runtime checks and records

Models return proposed actions. The runtime saves and validates them, and replies report only what the records show.

An example conversation

Check Saturday's weather in Tucson. Also find a time for dinner.

On it. I've started both.

After seven, please.

That goes to the dinner task only. The weather task's instructions don't change.

Saturday in Tucson looks sunny, around 82°F.

The result arrives without another message from the user. Follow this message through the system.

Where it stands

  • Working: durable chat at noribot.chat, several tasks at once, steering, Stop, budgets, questions that survive restarts, checked completion, and a persistent computer with shell and browser.
  • Deployed, no production task yet: web search, longer shell jobs, screenshots the model can read, calendar read, and finishing tasks from record checks and cited results.
  • Later: approvals and writes, subtasks, schedules, memory, proactive help and more clients.
  • Production is paused between live sessions to save money. Saved data stays. See the roadmap.
