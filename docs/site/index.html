How Nori works

Nori is Austin's assistant. You talk to it in one long conversation, and it does real work in the background while you keep talking.

The outer loop talks

It replies to Austin, starts tasks and passes along corrections. It stays quick because it never does the work itself.

Inner loops do the work

Each task gets its own loop with its own instructions and budget. One can wait or fail without affecting the others.

The runtime keeps it honest

Models propose things. Ordinary code saves them, checks them, and only reports what the records show happened.

An example conversation

Check Saturday's weather in Tucson. Also find a time for dinner.

On it. I've started both.

After seven, please.

That goes to the dinner task only. The weather task doesn't notice.

Saturday in Tucson looks sunny, around 82°F.

The result arrives on its own, without Austin asking. Follow this message through the system.

Where it stands

  • Working: durable chat at noribot.chat, several tasks at once, steering, Stop, budgets, a persistent computer with shell and browser.
  • Next: proper waits and checked completion, then web search, tool discovery and the calendar.
  • Later: approvals and writes, subtasks, schedules, memory, proactive help and more clients.
  • Production is paused between live sessions to save money. Saved data stays. See the roadmap.
