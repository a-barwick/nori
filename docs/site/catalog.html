Tool catalog

Every task's instructions list available capabilities, and a task loads optional or connected capabilities on demand before calling their tools.

Core controls outside the capability catalog are complete, capability_load, compose, request_input and request_work. The task's role decides which are supplied, and subtasks omit request_work.

What loading changes

  • Loading only adds tool definitions to later model calls. The runtime still checks every call against the task's scope and permission rules.
  • The loaded set lasts until the task ends. The worker reads it back from the saved transcript, so it survives a worker restart.
  • A capability with an unavailable key or disconnected server still appears in the catalog with its unavailable state so the model can explain why it cannot run rather than guessing.
What each catalog entry holds

The worker adds the catalog to the inner loop's instructions with today's date in the user's configured time zone. Each entry gives:

  • The capability's tools and its account or server label.
  • Availability, failure guidance and a verification rule.

All catalog text comes from metadata only. The worker never reads external content to build it.

The text changes at most once a day unless a connection or MCP server changes, so the provider's prompt cache still applies to the instructions.
