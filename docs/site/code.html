Code map

Where to look when you want to read or change something across the Go engine, clients, Home AI connectors, contract suite and simulation harness.

Go code lives under core/, the OpenAPI 3.1 API specification under api/openapi.yaml, the Next.js web client under web/src/, the native SwiftUI iOS client under ios/, Nori for Mac under macos/, the Linux Home AI connector packaging under connector/linux/, and the multi-day persona simulation suite under sim/personas/ and scripts/persona-sim/. Dependencies run in one direction: entrypoints build an app via platform, whose api routes and worker pool call conversation, task, permissions, scheduler, connections and connectors/mcp over state.

Infrastructure sits behind narrow contracts: state/postgres provides transactional JSONB records plus nori_task_leases, nori_user_wakes and LISTEN/NOTIFY, state/gcs and state/s3 handle cloud artifacts, wake wraps durable wake/repair helpers, and secret handles Secret Manager and envelope-encrypted Postgres rows.

The seven binaries core/cmd/

  • nori — Hosted service binary (--role=all|api|worker, --migrate-only; HS256 service-authenticated HTTP API and/or unified Postgres-native worker pool, GCP and AWS adapters).
  • nori-local — Loopback development binary running both the HTTP API and the unified Postgres-native worker pool in one process.
  • nori-user — CLI for provisioning users, managing invites, and binding verified identities in Postgres.
  • nori-sim — Virtual-clock simulation server used by the multi-day persona simulation and grading suite.
  • nori-connector — Home AI connector daemon and CLI bridging local Ollama hosts to the relay.
  • nori-connector-relay — Dedicated HTTPS/WebSocket relay forwarding encrypted Home AI requests between Core and paired connectors.
  • nori-storage-audit — Read-only audit tool inspecting artifact storage integrity and orphaned uploads.
