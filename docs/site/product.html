How we measure progress

Progress is verified by automated contract checks, deterministic simulations, multi-day persona evaluations and live multi-user integration gates rather than ad-hoc manual runs.

CheckWhat it proves
make api-checkValidates api/openapi.yaml (OpenAPI 3.1), verifies live Go HTTP handlers via kin-openapi, and checks generated TypeScript types for drift.
make checkRuns go vet, gofmt, Go unit tests, strict contract validation, TypeScript typecheck and ESLint across core/ and web/.
make sim-deep & make sim-pgRuns the deterministic simulation test suite (core/internal/sim/) checking invariants under crashes, races, restarts and Postgres concurrency.
make sim-personas-smoke / -memory / -fullDrives the 10-persona × 30-day real-LLM simulation and grading suite (sim/personas/, scripts/persona-sim/, core/cmd/nori-sim/) against virtual time.
Host app environment gateExercises the full message, MCP read/write approval and result flow across two distinct authorized identities, including SSE reconnects and strict cross-user isolation (404 on another user's resources).
Ten technical capabilities
CapabilityWhat it requires
Responsive chat, durable tasksConversation stays available while Postgres-native workers run with fenced leases and explicit checkpoints.
Explicit task stateTasks, commands, revisions, results and blockers are persisted in Postgres.
Separate memory storesExplicit user memory, compacted summaries, active work and permission rules stay separate with clear provenance.
Bounded context assemblyOuter turns stay under 96 KiB reply budget (128 KiB input cap); long task transcripts replace older tool outputs with retrievable operation IDs.
Ports and MCP tool busVersioned extension definitions pinned by digest, remote/local MCP clients and a provider-agnostic connections port.
Permission enforcementUniform deny-wins rule evaluation and action-digest-bound approvals across all tools and compose scripts.
Capability discoveryTask instructions list capabilities and availability; optional capabilities load tool schemas on demand.
Scheduling and inbox deliveryIANA time zones, deterministic occurrence IDs, generation fencing, goals and deduplicated in-app inbox delivery.
Artifact and result storageStable IDs, revisions, conflict preservation and private S3 or local object storage.
Cost, latency and evidence controlsMetered model spending, task budget ceilings, record-checked completion and correlated OpenTelemetry traces.
