When the outer model call fails

A failed outer model call ends the attempt with a published error reply and no accepted task commands.

Outer loopSends one request to the outer model for this attempt.
↓ error or unusable response
Was the attempt superseded during the call?
YesThe runtime publishes no error reply. The turn restarts with the newer batch.
NoThe runtime publishes an error reply. The turn completes with that reply.

What the user sees

FailurePublished reply
Request error or unusable responseText starts “I couldn't write a conversation reply” and includes the error from the request.
Invalid task commandsText says the model returned invalid tool calls and no task commands were accepted.

For a user message such as “Check Saturday's weather in Tucson”, the reply also says no new task commands were accepted and the message is saved.

What stays saved

  • The runtime saves the attempt as error and publishes the error text as the assistant message for the turn.
  • The runtime makes no second outer model call in that attempt. The runtime accepts no dispatch, steer, answer, continue or stop commands from the attempt.
  • A user message in the batch stays unresolved. The next user turn includes that message again as an input.
  • For each task event in the batch, the runtime re-reads the task after the failed call and appends its current saved status. The text quotes saved output for a finished task and copies the open question for a waiting task.
  • The runtime writes the usage record before it sends the provider request. A failed request can leave the cost in that record as unknown.

A Jev failure follows a different path. The turn continues without a hint, as the outer loop page shows.
