When the outer model call fails

A failed outer model call accepts no task commands, and publishes an error reply unless newer input restarted the turn.

Outer loopSends one request to the outer model for this attempt.
↓ error or unusable response
Did newer input replace the attempt during the call?
YesThe runtime publishes no error reply. The turn restarts with the newer batch.
NoThe runtime publishes an error reply. The turn completes with that reply.

What the user sees

FailurePublished reply
Request error or unusable responseText starts “I couldn't write a conversation reply” and includes the error. For a user message such as “Check Saturday's weather in Tucson”, it also says no new task commands were accepted and the message is saved.
Invalid task commandsText says the model returned invalid tool calls and no task commands were accepted.

What stays saved

  • The runtime saves the attempt as error and publishes the error text as the assistant message for the turn.
  • The runtime makes no second outer model call in that attempt (except a single reduced-context retry after a context-window overflow, dropping recent turns). The runtime accepts no dispatch, steer, answer or stop commands from a failed attempt.
  • A user message in the batch stays unresolved. The next user turn includes that message again as an input.
  • After a request error or unusable response, for each task event in the batch, the runtime re-reads the task after the failed call and appends its current saved status. The text quotes saved output for a finished task and copies the open question for a waiting task.
  • The runtime writes the usage record before it sends the provider request. A failed request can leave the cost in that record as unknown.

A failure in the Jev classifier follows a different path. The turn continues without its hint, as the outer loop page shows.
