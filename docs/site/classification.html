Classifying a message

Jev, a classifier model, marks the intents in the current user messages. The outer model gets them as a hint.

Current batch“Could you check when my domain renews?”
↓ batch and earlier messages
JevAnswers present or absent for each of nine intents.
↓ nine answers
How many intents are present?
OneIntent is that label. Confidence is that answer's confidence.
SeveralIntent is mixed. Labels are listed, with the lowest confidence.
NoneThe runtime sets converse. That fallback stores no confidence.
↓ hint, saved with the turn
Outer modelReads the hint and task records, then writes the reply and commands.

If the batch has no user message, the call fails, or any answer is missing or neither present nor absent, the hint is unavailable and has no intent label. The turn still calls the outer model.

The nine questions

Jev answers each question on its own. Present labels are saved in the order below.

IntentMeansExample
converseConversation, discussion or unclassifiable input“Let's discuss the architecture.”
askA question, with or without independent work“When is my appointment?”
request_workA request for independent work“Draft a reply to Sam.”
steerChanged instructions for existing work“Actually, use Thursday.”
provide_inputInformation, or an answer for existing work“His address is 12 Main Street.”
decideAn approval or another requested decision“Approve that draft.”
inspectA question about existing work or its outcome“Did you send it?”
controlA request to stop or control existing work“Stop the research.”
update_memoryAn explicit request to change persistent memory“Remember that I prefer evenings.”
  • Jev reads the batch in order, and a later message can correct an earlier one.
  • Earlier conversation only resolves a reference such as “Thursday”.
  • The questions leave out tools, access and reply format.

How the question wording should change is on Open questions.

What Jev receives

PieceSent
Current user messagesYes, in acceptance order. They are not also copied into the history.
Earlier visible messagesYes. Role and text only. Task records there are marked as background.
User messages accepted after this batchNo.
Introduction, or a task notificationNo. Neither is a user message, so a batch of only those does not call Jev.
Saved model protocolNo. The outer model receives it with the turn.

A task panel answer, steer, continue, stop, or direct task update is saved as a command and is not classified. See Service API.

What the outer model receives

The runtime saves the hint before the outer model call. A restart for a newer message classifies the new batch.

The hint sits beside the task records as context. Confidence doesn't allow or block a command. “Could you check when my domain renews?” can be an ask alone, and the outer model can still dispatch a lookup.

How Jev calls are recorded

Before calling Jev, the runtime records provider jev and model jev-latest with an unknown cost. Jev returns no verified price. If that record fails, the request is not sent.
