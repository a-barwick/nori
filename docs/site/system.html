Service overview

One agent service runs the assistant and independent chats, with saved state shared across its processes.

Browser clientsThe assistant and chat client send messages through the same Next.js server.
↓ owner-checked HTTP requests
Go agent serviceSaves inputs and runs conversation turns.
↓ accepted conversation work
Assistant outer loopReplies, dispatches tasks and sends task commands.
Foreground chat serviceStreams a separate chat's reply and runs its permitted tools.
↓ messages, events, task records and usage
FirestoreKeeps existing assistant records and separate records for each chat.

How work runs

PartResponsibility
Assistant outer loopBuilds conversation replies and accepts background tasks without waiting for task execution.
Temporal and task workerRun each task's inner loop, preserve waits and deliver recorded outcomes.
Foreground chat serviceUses the outer model directly for a saved chat turn. Tools use shared reading and approval code.
Cloud Tasks or local loopWake processing for saved conversation work.
Persistent computerProvides the shell and browser used by assistant tasks.

“Check Saturday's weather in Tucson” can run as an assistant task while a separate chat answers “Total the parts in this CSV”.

What stays separate

  • Each chat has its own messages, attachments, events, active turn and approvals.
  • Existing assistant messages, task IDs and pending questions keep their original record paths.
  • Foreground chat context excludes assistant tasks and saved memories.

Both paths use the configured outer model and the same development spending controls. A new conversation ID grants no additional allowance.

Where state lives

StoreRecords
FirestoreAccepted inputs, chat snapshots, conversation events, task commands and display records.

Records and delivery covers task records. Chat client covers foreground limits and controls.
