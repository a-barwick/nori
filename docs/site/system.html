Service overview

One multi-user Go binary (cmd/nori --role=all|api|worker) runs the assistant outer loop, management APIs and Postgres-native durable task pool over Postgres and S3.

The host app (or local test workbench)Verifies user identity and maps it to a provisioned Nori user ID.
↓ HS256 service-authenticated HTTP under /users/{id}/v1/*
Go API (nori --role=all|api)Saves inputs, writes durable wakes/leases, serves SSE streams and management APIs.
↓ durable Postgres wakes, leases & NOTIFY nori_wake
Inner task pool (worker.Pool)Claims nori_task_leases and runs each task's task.Runner, durable waits, approvals and MCP tool calls.
Outer & scheduler lanes (worker.Pool)Claims nori_user_wakes to run conversation turns and due automations.
↓ messages, events, task records, leases, encrypted credentials and usage
Postgres & S3Stores user-scoped records, leases and wakes in Postgres and private file bytes in S3 (or local disk).

How work runs

PartResponsibility
Outer loop (conversation)Holds one persistent thread per user, guards dispatches against prompt injection, manages explicit memory and accepts background tasks without blocking.
Inner loop (task, agent, worker)Runs each task in task.Runner with document-fenced leases (TaskControl), budgeted turns, steering, durable waits and record-checked completion.
Ports & MCP (connections, connectors/mcp, extensions, invoke)Exposes built-in capabilities, remote/local MCP servers and provider-agnostic connections through one permission-checked executor.
Permissions (permissions)Evaluates deny-wins rules and manages action-digest-bound approval interactions.
Scheduler (scheduler)Runs recurring automations and goals, delivering results to the in-app inbox.
Unified worker pool (worker.Pool)Listens on LISTEN nori_wake with a 2-second fallback poll and 60-second repair sweep to drive outer conversation turns, due schedules and inner task runners.

User isolation

  • Every user-scoped route sits under /users/{id}/..., resolved on the server from a verified host app session or OIDC ID token.
  • Conversations, tasks, interactions, approvals, MCP servers, credentials, results and uploads are isolated per user. Requesting another user's resource ID returns 404.
  • Hosted API entrypoints require short-lived HS256 service tokens (core/internal/serviceauth). Only /healthz and /readyz are unauthenticated.

Records and delivery covers the record layout and Postgres-native wake/lease model. Deployment covers AWS and local topology.
