Words we use

The same words mean the same things on every page.

WordWhat it means
OfferA message the runtime adds to the conversation with no request from the user, such as a calendar offer.
ScheduleA saved reminder, later task or monitor the user asked for, with a rule in local time. See Schedules.
MonitorA schedule that runs a read-only check on a cadence and adds a message only when the check reports what the user asked to hear about.
Saved resultThe record of a task's answer, file, screenshot or link, with a stable ID. See Results and files.
Log eventA numbered entry in the event log, naming a message, task or result that changed. Clients follow them on a stream. See Service API.
Work requestA task's request for work outside its own instructions. The task waits until the outer loop settles it.
SubtaskA task the outer loop starts for another task's work request. That other task is its parent, which waits for the outcome and whose budget covers the cost.
Outer loopThe part of Nori that holds the conversation. It runs one short turn at a time.
Inner loopThe loop that does one task: call the model, run tools, save results, repeat.
RuntimeGo code around the loops that saves, checks and delivers records. It isn't a model.
Agent serviceThe Go code in core/ that clients call. It runs the outer loop and the runtime, and starts tasks.
ClientAn app a person uses to reach Nori, such as the web client. It sends messages and task commands, and shows saved state from a snapshot and the event stream.
TaskOne piece of independent work, with one ID for its whole life.
TurnOne run of the outer loop, from claiming messages to publishing a reply.
AttemptOne saved try at a turn. A restart for a newer message starts a new attempt.
DispatchThe outer loop starting a new task.
SteerNew instructions for a running task. Earlier constraints stay unless replaced.
CommandA saved instruction going to a task: start, steer, answer, continue, approve, decline or stop.
EventA saved report coming back from a task, such as a result or a question. A log event is a different record.
InboxThe ordered Firestore list of inputs waiting for the outer loop.
AcceptedSaved. It doesn't mean anything has happened yet.
AppliedA task has read the command and is working from it.
RevisionA counter that goes up when instructions change, so stale decisions can be caught.
PositionWhere a command sits in a task's ordered list, so nothing is read twice.
Lease and fenceHow one turn claims the conversation, and how a stale turn is kept from writing.
OperationOne tool call with a stable ID, recorded before it runs.
ReceiptThe guest's record of what an operation did. It's used instead of guessing.
RelayThe code that delivers saved commands from Firestore to Temporal until acknowledged. The code calls it the dispatcher.
ProjectionA copy of task state in Firestore for display. The workflow holds the authoritative figures.
IntentOne label Jev can mark on the current user messages, such as ask or steer. Several labels can be present on one batch.
JevThe fast classifier that gives the outer loop a hint. It can't grant anything.
ComputerNori's persistent Linux machine, with a shell and a browser.
Guest and hostThe guest is the Firecracker machine tasks use. The host is the GCE VM it runs on.
Computer providerThe Go interface that opens or attaches to the computer. An adapter implements it for one kind of infrastructure, such as GCE or a loopback address.
WorkerThe process that runs inner loops, and the tools that don't need the computer.
JobA background shell command on the computer that belongs to one task and can run for up to 60 minutes.
ArtifactA screenshot a task saved. A saved result can point to one.
Trace and spanA span is one timed operation, such as a model call. A trace is the set of spans that share a trace ID, such as those for one message. See Observability.
PauseThe project-wide switch. It stops new execution, and chat keeps working.
StopEnds one task and confirms it stopped.
TranscriptThe ordered messages of one task: the request, later steers and answers, model turns, tool calls and tool results. It is saved as private history.
