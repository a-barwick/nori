Workbench architecture

The slim Next.js test workbench talks to its own server proxy, which checks authentication and origin before calling the Go agent service.

Request path

↓ same-origin /api/ requests and an SSE stream
Next.js serverVerifies OIDC (on AWS) or local loopback dev identity, checks origin and attaches an HS256 service token.
↓ /users/{id}/... with service credentials

The browser never calls a model provider directly and never holds service tokens.

Sending a message

React clientGenerates a UUID for the message and stores a pending copy locally.
↓ POST /api/turn
Agent serviceSaves the message in Postgres and enqueues a wake.
↓ snapshot listing the UUID
React clientClears its pending copy.
↓ later, an SSE event with the whole reply
React clientDisplays the reply.
  • If a response is lost, Retry sends the exact same UUID. Pending messages also resend after a reload, reconnect or manual refresh.
  • A message can be up to 8,192 UTF-8 bytes, and up to 20 messages can be pending.
  • Task commands work the same way, with their own stored queue. A command clears once accepted or once a snapshot shows the task applied it.
  • A 4xx response marks a command as rejected and offers Edit; transient failures offer Retry.

Merging, sign-in, telemetry and builds

How snapshots merge

  • A snapshot with an older conversation revision, or the same revision from an older request, is ignored.
  • Messages and traces merge by ID, so older pages stay loaded.
  • A saved task only replaces the one in memory if its position, event sequence, applied commands, status and Stop flag have not moved backward.

Sign-in and limits

  • Hosted AWS deployments verify OIDC ID tokens via jose JWKS discovery (NORI_OIDC_ISSUER, NORI_OIDC_AUDIENCE, NORI_OIDC_COOKIE) by default, and still retain NORI_AUTH_PROVIDER=iap for IAP-fronted deployments. Unsigned identity headers are never accepted.
  • POST routes require a matching Origin, and reads require same-origin fetches. Browser credentials are never forwarded to the agent service; the server mints 1-minute HS256 service tokens.
  • The hosted proxy allows JSON bodies up to 128,000 UTF-8 bytes (64,000 bytes in local mode) and waits up to 145 seconds; streams and uploads wait up to 170 seconds.
  • On local loopback development, the local identity flow passes and proxies to NORI_LOCAL_AGENT_URL.
  • /api/health is the only API route without user authentication.

Telemetry

  • The layout injects public Sentry settings into data-nori-observability at request time so one image moves between environments.
  • useRuntime measures submit-to-reply latency as nori.submit_to_reply (15-minute cap) and attaches W3C traceparent headers on turn.
  • Privacy filters in web/src/lib/observability/privacy.ts strip sensitive payloads before export. Browser Sentry envelopes go through /sentry-tunnel (web/src/app/sentry-tunnel/route.ts), which verifies authentication and strips request headers before forwarding. See Observability.

Builds

The test workbench uses Next.js, React and Tailwind. Run make dev to start local Go + Next.js, and make check to run TypeScript typecheck and ESLint alongside Go and contract checks. See Deployment for hosted topology.
