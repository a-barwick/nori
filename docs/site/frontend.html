Web client architecture

The assistant browser client talks to a Next.js server, which checks access before calling the agent service.

Request path

React clientNoriApp and its components use useRuntime for requests and saved state.
↓ same-origin /api/ requests and an event stream
Next.js serverChecks the owner, origin and operation, then adds a Google token.
↓ the same requests with server credentials
Agent serviceSaves commands and sends log events. See Service API for the endpoints.
OperationClient use
v1/snapshotLoads a snapshot, or an older page with before.
v1/eventsFollows the event stream.
v1/uploadsUploads an attached file when it's picked.
turnSends a message with a client-made UUID.
commandSends steer, answer, continue or stop for one task.

deliveredReports saved results from replies shown in the visible conversation viewport.

The client never calls a model. Its Chats tab uses the same authenticated server.

Sending a message

React client“Check Saturday's weather in Tucson” gets a UUID and is saved locally.
↓ POST /api/turn
Agent serviceSaves the message.
↓ snapshot listing the UUID
React clientRemoves its pending copy.
↓ later, a log event with the whole reply
React clientShows the reply.
  • If a response is lost, Retry sends the same UUID. Pending messages also resend after a reload, reconnect or manual refresh.
  • A message can be up to 8,192 UTF-8 bytes, and up to 20 messages can be pending.
  • Task commands work the same way, with their own stored list. A command clears when the agent service accepts it or a snapshot shows the task has applied it.
  • A 4xx response marks a command as rejected, and the panel offers Edit. Any other failure offers Retry.

Merging, sign-in, telemetry, components and builds

How snapshots merge

  • A snapshot with an older conversation revision, or the same revision from an older request, is ignored.
  • Messages and traces merge by ID, so older pages stay loaded.
  • A saved task only replaces the one in memory if its position, event sequence, applied commands, status and Stop flag haven't moved backward.

Sign-in and limits

  • Production requires Google IAP sign-in. The server verifies the signed assertion and the owner's email, and ignores unsigned identity headers.
  • POST routes require a matching Origin, and reads require a same-origin fetch. Browser credentials are never forwarded to the agent service.
  • The hosted route allows JSON bodies up to 128,000 characters and waits up to 145 seconds. Streams and uploads wait up to 170. The agent service URL must use HTTPS.
  • In development on loopback, the owner check passes. If NORI_LOCAL_AGENT_URL is set, the client uses /api/agent/{operation} instead, with limits of 64,000 characters and 100 seconds.
  • /api/health is the only API route with no owner check.

Telemetry

  • The layout writes public Sentry settings to data-nori-observability at request time, so one image can move between environments.
  • useRuntime records the time from submit to reply as nori.submit_to_reply, with a 15-minute timeout, and sends trace headers on turn.
  • Filters in lib/observability/privacy.ts run before events, spans, logs and metrics are sent. The sentry-tunnel route checks the owner and strips request headers before forwarding.

Components

The runtime hook owns requests and saved state. The thread owns scrolling, viewport reporting and new-message counts. See Code map for other components.

Builds

The assistant uses Next.js, React and Tailwind. See the repository README for guarded local commands, and Deployment for hosting.
