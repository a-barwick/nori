Workbench architecture

The slim Next.js test workbench talks to its own server proxy, which checks authentication and origin before calling the Go agent service.

Request path

React clientChatScreen and the screen components call the assistant API through useRuntime.
↓ same-origin /api/ requests and an SSE stream
Next.js serverVerifies the user (OIDC on AWS, a local identity in development), checks the origin and attaches an HS256 service token.
↓ /users/{id}/... with service credentials
Agent service (nori)Saves records in Postgres and streams events. See Service API.
OperationClient use
v1/snapshotLoads the assistant snapshot, or an older page with before.
v1/eventsFollows the resumable SSE event stream.
v1/uploadsUploads an attached file with a client UUID.
v1/* management routesReads and changes Work, interactions and approvals, MCP servers, connections, automations, goals, library and memory.
turnSends a message with a client-generated UUID.
commandSends steer, answer or stop for one task.
artifactFetches a saved artifact.
seenReports a reply shown in the viewport.
deliveredReports saved results from replies shown in the viewport.
traceFetches task step traces for an open debug row.

The browser never calls a model provider and never holds service tokens.

Sending a message

React clientGenerates a UUID and stores a pending copy.
↓ POST /api/turn
Agent serviceSaves the message in Postgres and enqueues a wake.
↓ snapshot listing the UUID
React clientClears its pending copy.
↓ later, an SSE event with the whole reply
React clientDisplays the reply.
  • If a response is lost, Retry sends the same UUID. Pending messages also resend after a reload, reconnect or manual refresh.
  • A message can be up to 8,192 UTF-8 bytes. Up to 20 messages can be pending.
  • Task commands use their own stored queue. A command clears once accepted or once a snapshot shows the task applied it.
  • A 4xx response marks a command as rejected and offers Edit. Transient failures offer Retry.

Live updates

SituationClient behavior
The tab is visibleFollows the SSE stream and merges each record by ID.
A reply enters the viewportReports it as read (seen) and acknowledges its saved results (delivered). Failed reports retry.
A reply stays below the viewportNeither its results nor the shared read position advance.
Nothing has run for 5 minutesCloses the stream, and reopens it on focus or a new message.
The tab is hiddenCloses the stream, then fetches a fresh snapshot when the tab is visible again.
The stream sends resetFetches snapshots until one succeeds, then streams from its position.
A response isn't a streamReopens from the last event sequence, with backoff up to 30 seconds. After 3 failures it shows a reconnecting status.

A reply's results count as delivered once a visible session displays it.

Merging, sign-in and telemetry

How snapshots merge

  • The client ignores a snapshot with an older conversation revision, or the same revision from an older request.
  • Messages and traces merge by ID, so older pages stay loaded.

Sign-in and limits

  • Hosted AWS deployments verify OIDC ID tokens through jose JWKS discovery. Setting NORI_AUTH_PROVIDER to iap selects IAP-fronted deployments. The server never accepts unsigned identity headers.
  • POST routes require a matching Origin, and reads require same-origin fetches.
  • The server mints 1-minute HS256 service tokens and never forwards browser credentials.
  • In local loopback development, the proxy forwards to NORI_LOCAL_AGENT_URL.
  • /api/health is the only API route without user authentication.

Telemetry

  • Privacy filters strip sensitive payloads before export. Browser Sentry envelopes go through /sentry-tunnel, which verifies authentication and strips request headers. See Observability.
