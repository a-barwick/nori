Budgets and controls

Nori meters every model call and uses four controls to bound spending, pause execution or stop work.

Inner model callA task calls its model and records usage before and after the request.
↓ calculated or reported cost
Runner adds to spentThe task's spent figure grows between calls.
↓ spent reaches ceiling ($1 default)
Task ends incompleteStops without a model call and saves an incomplete outcome with its work.
  • The $1 default ceiling (NORI_TASK_BUDGET_USD) is checked between calls. It bounds further turns and doesn't cut off a response in progress.
  • Each web search adds $0.005 to the task's spent figure.
  • A subtask's cost counts against its parent's budget, and each check reads the shared total from Postgres. Each running subtask can overrun by one model response and its tool calls.
  • If a call has no cost, or an incompatible one, the usage row and task checkpoint set the cost_status value unknown. A successful result stays valid.

Four controls

Task budget · $1

Covers a top-level task and its subtasks. At the ceiling the task ends incomplete, with progress saved.

Input & approval wait

The task parks in Postgres (runnable = false and waiting_reason in nori_task_leases) with its question or approval card intact. No timer ends it, and it holds no worker or lease.

Pause

Blocks new task admission while the conversation and saved records stay readable. Workers save returned replies and completed subtask outcomes before exiting.

Task Stop

Ends one task and its subtasks, and confirms pending operations stopped.

Usage metering

usage.Meter accepts an idempotent usage record before and after each model request.

  • Startup selects the Postgres meter by default. Setting NORI_USAGE_METER=http with NORI_USAGE_ENDPOINT and NORI_USAGE_TOKEN adds a host endpoint without changing model callers. The endpoint requires HTTPS except on loopback.
  • The host receives {user_id, usage} with the request ID, model, token counts, cost and request status. It receives no prompts or files.
  • The receiver upserts by user and request ID. The HTTP idempotency key also includes the request status.
  • Database recording is always on. If host admission fails, no provider call is sent and the local record becomes not_sent.
  • If final delivery to the host fails, Nori logs the request ID and keeps the result and the local usage record. There is no retry queue, so a host reconciles from those records. Pending records after a process crash stay unresolved.
  • Each user also has admission limits, by default 300 calls per hour (NORI_USER_MAX_CALLS_PER_HOUR) and $15 per day (NORI_USER_MAX_USD_PER_DAY). A call over a limit is not sent to the provider.

Continuing after the limit

A task that reaches its spending limit stops with its work and results saved. It publishes status: "failed" with expected_incomplete: true.

  • From Work, the user can continue it with a new limit. That starts a new task linked to the stopped one, titled after the original request.
  • A continuation can raise the limit up to $50. Ordinary tasks can only lower it.
