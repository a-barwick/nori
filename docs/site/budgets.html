Budgets and controls

Nori counts model spending and uses four controls to pause or stop work.

  • The $1 limit is checked between calls, so it isn't a hard cap on billing.
  • Each web search adds $0.005 to the task's spent figure.
  • Missing cost is recorded as unknown and does not invalidate a successful result.
  • A subtask's cost counts against its parent's budget, and each check reads the shared total from the store. Each running subtask can overrun by one model response and its tool calls.
  • Outer, chat, Jev, compaction, inner-task and image-inspection calls share the usage meter.

Four controls

Task budget · $1

Applies to a top-level task and its subtasks. The configured NORI_TASK_BUDGET_USD ceiling defaults to $1. Reaching it saves an incomplete outcome; there is no repeated budget-grant flow.

Input wait

The task parks with its question and records intact. No timer ends it.

Pause

Blocks new execution and stops the computer while chat keeps working.

Local workers save returned replies and completed subtask outcomes before exiting. Parents read those outcomes after resume.

Task Stop

Ends one task and its subtasks, and confirms their operations and shell jobs stopped.

Operating rules

  • Cloud Run and Agent Runtime run with a minimum of 0 and a maximum of 1 instance.
  • When live work finishes, worker pools scale to zero and the computer stops.
  • The computer's guest receives no cloud credentials.

Usage metering

usage.Meter accepts an idempotent usage record before and after each model request. Startup selects the database meter by default. NORI_USAGE_METER=http, NORI_USAGE_ENDPOINT and NORI_USAGE_TOKEN add a host endpoint without changing model callers. The endpoint requires HTTPS except on loopback.

The host receives {user_id, usage}, with stable request IDs, model, token counts, cost and request status. It receives no prompts or files. The receiver upserts by user and request ID; the HTTP idempotency key also includes the observation status. Missing cost stays absent with cost_status=unknown.

Database recording always remains enabled. If host admission fails, no provider call is sent and the local record becomes not_sent. If final delivery fails, Nori logs the request ID and retains the result and local usage record. There is no delivery retry queue; a host can reconcile from those records. Pending records after a process crash remain explicitly unresolved.

The task workflow still enforces its spending ceiling between calls. Ordinary project keys are used; there are no temporary keys, reservations, daily or monthly development caps, or per-chat grants. The configured model roles and reasoning settings are unchanged.

Continuing after the limit

A task that reaches its spending limit stops with its work and results saved and says it is incomplete. From Work the user can continue it with a new limit: that starts a new task linked to the stopped one, titled after the original request, and the stopped task shows what continued it. A continuation can raise the limit (up to $50); ordinary tasks can only lower it.
