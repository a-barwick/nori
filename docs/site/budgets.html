Budgets and controls

Nori meters every model call and uses four controls to bound spending, pause execution or stop work.

Inner model callA task calls its model and records usage before and after the request.
↓ calculated or reported cost
Runner adds to spentThe task's spent figure grows between calls.
↓ spent reaches ceiling ($1 default)
Task ends incompleteStops without a model call and saves an incomplete outcome with its work.
  • The $1 default ceiling (NORI_TASK_BUDGET_USD) is checked between calls, so it bounds further turns rather than cutting off an in-flight response.
  • Each web search adds $0.005 to the task's spent figure.
  • Direct OpenAI tariffs (core/internal/usage/openai.go) price cached input tokens at 1/20th of uncached input: gpt-6.1-sol at $2/M input, $0.10/M cached input and $10/M output; gpt-6.1-terra at $1/M input, $0.05/M cached input and $5/M output (long-context > 272k input: $2/M, $0.10/M and $7.50/M).
  • Missing or incompatible cost is recorded as cost_status=unknown on the usage row and task checkpoint without failing or invalidating a successful result.
  • A subtask's cost counts against its parent's budget, and each check reads the shared total from Postgres. Each running subtask can overrun by one model response and its tool calls.
  • Outer, Jev, compaction, inner-task and image-inspection calls all share the usage meter.

Four controls

Task budget · $1

Applies to a top-level task and its subtasks. Reaching the ceiling ends the task incomplete with its progress saved; there is no continue budget question.

Input & approval wait

The task parks in Postgres (runnable = false and waiting_reason in nori_task_leases) with its question or typed approval card intact. No timer ends it.

Pause

Blocks new task admission while the conversation and saved records stay readable. Workers save returned replies and completed subtask outcomes before exiting.

Task Stop

Ends one task and its subtasks, and confirms pending operations stopped.

Operating rules

  • Waiting tasks hold no worker goroutines or active leases while parked on a question or approval.
  • Postgres NOTIFY nori_wake hints carry only minimal routing metadata, never conversation content or credentials.
  • Hosted API entrypoints require short-lived (1-minute) HS256 service tokens; browsers never hold service credentials.

Usage metering

usage.Meter accepts an idempotent usage record before and after each model request. Startup selects the Postgres meter by default. NORI_USAGE_METER=http, NORI_USAGE_ENDPOINT and NORI_USAGE_TOKEN add a host endpoint without changing model callers. The endpoint requires HTTPS except on loopback.

The host receives {user_id, usage}, with stable request IDs, model, token counts, cost and request status. It receives no prompts or files. The receiver upserts by user and request ID; the HTTP idempotency key also includes the observation status. Missing cost stays absent with cost_status=unknown.

Database recording always remains enabled. If host admission fails, no provider call is sent and the local record becomes not_sent. If final delivery fails, Nori logs the request ID and retains the result and local usage record. There is no delivery retry queue; a host can reconcile from those records. Pending records after a process crash remain explicitly unresolved.

The task runner still enforces its spending ceiling between calls. Ordinary provider or model-gateway keys are used; there are no temporary keys or daily/monthly development caps inside Nori.

Continuing after the limit

A task that reaches its spending limit stops with its work and results saved and publishes status: "failed" with expected_incomplete: true. From Work the user can explicitly continue it with a new limit: that starts a new task linked to the stopped one, titled after the original request, and the stopped task shows what continued it. A continuation can raise the limit (up to $50); ordinary tasks can only lower it.
