Budgets and controls

How Nori keeps spending visible, and the four different ways work can pause or stop.

There are four separate controls here, and they're easy to mix up. On cost:

  • Model cost is calculated inside the workflow from reported usage and list price.
  • The $1 limit is checked between calls to decide whether to pause, so it isn't a hard cap on billing.

Task budget · $1

Applies to each top-level task. When it runs out, the task saves its progress and asks, and continue adds $1. Reporting the pause doesn't use a model call.

Input / dependency wait

The task parks with its identity, question and records intact. No timer ends it.

Project pause

system/control.paused blocks new execution. Workers exit and the computer stops, while chat keeps working and data is retained.

Task Stop

Ends one task, confirms the computer stopped, and reports any effects that already happened.

Operating rules

  • Cloud Run and Agent Runtime run with a minimum of 0 and a maximum of 1 instance.
  • When live work finishes, worker pools scale to zero and the computer stops.
  • Credentials are in the gitignored root .env (mode 600) and are kept out of model context, logs and workflow history.
