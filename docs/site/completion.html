Finishing a task

Milestone 4 adds saved-evidence checks and a Jev verdict before a task can finish.

Implemented in PR #30, which is not merged.

The nori-task-v2 workflow on main still ends on a plain text answer.

The decision table

The row comes from what the task attempted, read from its records. “Check the weather and add a picnic” counts as a write once it tries the calendar.

If Jev is unavailable, publish the proposed answer as unverified and explain what could not be checked. The task is not completed.

What this catches

What's the weather in Phoenix? Actually, Tucson.

An answer about Phoenix can't be published, because the instructions changed while it was being written.

Did you send it?

Nori answers from the receipt, or checks with the provider. A status question never sends anything again.

  • Every check is logged so the 0.8 threshold can be tuned from the logged results.
  • The check covers completeness. It doesn't prove every fact in the answer is true.
Evidence and telemetry

Each check reads the current request, accepted corrections, ordered tool calls, input answers and cited saved results. Asking which bill to read before opening it can be checked from that order.

Private history references bind the task, parent and exact bytes. Temporal carries references instead of the cumulative transcript. Old workflows retain their original behavior.

The check saves its verdict, confidence, revision and position. Sentry and Arize receive correlated spans and operational attributes; private history and credentials are excluded by default.

Local collector checks exercise both exporter paths. They do not establish ingestion by the hosted Sentry or Arize projects.
