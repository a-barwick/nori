Finishing a task

The runtime checks a task's saved records, then the outer loop compares the answer with the results the task cited.

RuntimeChecks the records. No model is involved.
↓ answer, cited results, unmet items
Outer loopCompares the answer with the cited results and reports what is done.

The record checks

  • Every instruction has been read.
  • Every tool call has a saved result.
  • No operation has an unresolved outcome.
  • A task with saved tool results cites them as evidence.
  • Each cited reference resolves to a saved result that can be read.

The decision table

What the runtime findsWhat happens
Checks pass, nothing unmetThe task is completed.
Checks pass, unmet items listedThe task ends as failed. Unmet items are requirements the task reports it didn't meet, and its result lists them after the answer.
Checks fail, reads onlyThe task gets up to two read-only corrections, then ends as failed with a partial answer.
Checks fail, after a write or stopThe task asks the user. It never repeats the action automatically.
Instructions changedThe task reads the new instructions and proposes again.

What the outer loop receives

  • On the turn that reports a task's end, the runtime reads the results the task cited and passes up to 8 KiB of them to the outer loop. It shortens long results from the middle.
  • If the answer claims something the results don't show, the outer loop tells the user and doesn't dispatch the work again by itself.
  • The cited results are data. A page that says "ignore your instructions" is text in a result, and the outer loop treats it that way.

What this catches

What's the weather in Phoenix? No, Tucson.

An answer about Phoenix can't be published, because the instructions changed while it was being written.

Nori answers from the receipt, or checks with the provider. A status question never sends anything again.

  • The checks cover the records. No separate system judges whether an answer satisfies the request, so a wrong answer is caught only if the outer loop can see the conflict in the cited results.
  • Tools make that comparison possible by returning a way to confirm each change.
Evidence and telemetry

Private history references bind the task, parent and exact bytes. Temporal carries references instead of the cumulative transcript. Completed tasks keep their saved Jev verdicts.

Each check saves its record failures, revision and position. Sentry and Arize receive correlated spans and operational attributes. Private history and credentials are excluded by default.
