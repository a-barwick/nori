Memory recall and screen

The outer loop, tasks and the user each read saved memory in a different way, and the user can also edit it.

ReaderHow it readsWhat it gets
Outer loopSearches Daily Logs on each user turn.Up to 5 snippets, 2560 bytes in total, in the advisory message.
TaskCalls the memory tools.Core Memory, Working Memory, ranked snippets or full entries.
UserOpens /memory or searches with GET /v1/search.All three tiers, with edit controls.

Postgres FTS index & tail auto-recall

The search index is the nori_memory_chunks table, split into 32 hash partitions by owner.

  • Each chunk is indexed with the english and simple text search dictionaries, so exact identifiers and emails match along with stemmed words.
  • Core items rank at 1.0, or 1.15 when pinned. Daily Log hits lose half their score every 30 days.
  • The top hits are reranked to avoid near-duplicates, and each snippet is cut to 700 bytes.
  • The outer loop searches only the log layer, for 5 hits created after ContextFrom, and adds them to the advisory message after the cached prefix.

Inner-loop recall tools

Tasks get these read tools by default. They return only entries created at or after ContextFrom, and they grant no permissions.

ToolReturns
memory_readCore Memory items and the current Working Memory summary.
memory_searchRanked snippets from Core Memory and Daily Logs, with a layer filter and a limit from 1 to 20.
memory_getAll Core Memory (target: "core"), or one Daily Log date or entry (target: "log").
conversation_find and conversation_readMatches in earlier chat messages, and full reads of them.
operation_read and task_history_readSaved outputs that the task transcript replaced, and older transcript blocks.

See Task transcript for how long task histories are shortened.

Unified /memory screen, receipts & global search

/memory shows all three tiers, and /settings/memory redirects to it.

TabControls
Core MemorySearch, add, edit, pin, unpin, demote to log and forget. It shows each item's provenance and a meter of bytes used out of 24 KB.
Daily LogsA timeline by date with search, forget, and promote to Core. A task_outcome entry must be reviewed before promotion.
Working MemoryThe gist and summary items, with promote to Core and dismiss. A Consolidate now button starts AutoDream.
  • Each /v1/memory change saves a receipt that GET /v1/mutations/{request_id} returns.
  • Reusing a request ID for a different change returns 409 idempotency_conflict. A stale revision returns 409 revision_conflict with the current version.
  • A memory change sends an SSE memory event, and GET /v1/search returns memory hits.
