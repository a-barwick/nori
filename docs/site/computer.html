Persistent computer

A small Linux machine that tasks use for shell and browser work. It keeps its files between runs.

If the worker opens a weather page for “Check Saturday's weather in Tucson,” the browser returns the page's text.

  • Kept across guest restarts and host replacement: files, installed tools and the browser profile.
  • Lost on restart: running processes and open tabs.
  • Access uses Google's authenticated tunnel to the host proxy, which forwards calls to the guest.
  • Browser tabs share cookies, so tasks aren't isolated from each other.

Receipts make retries safe

The guest records the request and response for each operation ID before acknowledging. If a shell command's outcome is uncertain, the worker reads the receipt and doesn't run it again.

The host says when it's draining

When the host is stopping because it's idle, it rejects requests with a draining header before forwarding them. This is the one case where it's safe to reconnect and resend.

Jobs belong to a task

The guest runs each long shell job for one task and saves its state on disk. A job without a saved final state is reported as lost after restart.

Attached files and programs

The worker copies an attached file into the task's uploads folder, read-only. A task can save a file from its folder as a saved result, and the guest refuses a path outside that folder. The guest has python, and a service inside it installs pdftotext on the first boot that lacks it.

Adapter calls

An adapter with a power state implements three calls. A shared loop polls State once a second, reports Stopped only after the host has finished stopping, and never sends a start during Stopping.

Taking over the computer

The user can take over the computer, for example to sign in somewhere. Taking over gives the user a 15-minute lease that can be renewed. While the user holds it, a task that needs the computer stops before touching the screen and waits with a takeover request in Work; other tasks are refused and listed as waiting. Resuming names the lease, the task and the task's current instruction revision, so a stale resume is refused. The resumed task gets a fresh run on the computer: calls cancelled when the user took over stay cancelled, and new calls go through.

Checking whether the computer is available never starts a stopped computer.
