Persistent computer

A small Linux machine that belongs to Nori. Tasks use its shell and browser, and it keeps its files between runs.

The computer is a retained workspace for the inner loop.

  • Kept across guest restarts and host replacement: files, installed tools and the browser profile.
  • Lost on restart: running processes and open tabs. The inner loop is told that process state may have changed.

Receipts make retries safe

The guest records the request and response for each operation ID before acknowledging. If a shell command's outcome is uncertain, it's reconciled against the receipt and isn't simply run again.

The host says when it's draining

When the host is stopping because it's idle, it rejects requests with a draining header before forwarding them. This is the one case where it's safe to reconnect and resend.

The model can't see the browser yet

It can navigate and read page text. Screenshots are saved for Austin, but the model doesn't see them. Vision is planned for milestone 5 (AB-203).
