Confirming a change

A tool that changes something must come with a way to confirm the change. The inner loop runs the confirmation and cites it in complete, and lists anything it couldn't confirm as unmet.

ToolHow the change is confirmed
job_startjob_wait returns the end state, exit code and output.
job_stopIts result is the final state, once the processes have exited.
shellThe exit code shows the command ran. A follow-up read, such as a file count, shows its effect.
Future connectorsA write returns the provider's status and the ID it changed, and names a read that confirms it. An upload returns a 200 and a file ID, and a GET on that ID confirms it. designed

Long shell jobs

running→finishedorstoppedortimed_outorlost
  • A job can run for up to 60 minutes, with up to 4 running per task. It belongs to the task, so a correction or a question leaves it running.
  • job_wait makes no model calls. An activity reads the job's state every 15 seconds and saves the latest output line as the task's progress, which the web client and the outer loop read.
  • One worker stays running while a task waits on a job, because a pending activity is what wakes a request worker.
  • The task can't propose completion while a job it started is running, and terminal cleanup stops any job still running.
  • A running job holds off the computer's idle stop. If the guest restarts or the computer stops, the job's state is lost, and the runtime never reports it as finished.

Reading a screenshot

  • screenshot_inspect sends one saved image and one question to the task model in a separate call with no tools.
  • Only the text answer joins the task's history. The image isn't resent on later turns, and text inside it can't call a tool.
  • The cost counts against the task's budget.
  • The outer loop receives that text answer when the task cites it, because it doesn't receive images.

The calendar connection

  • nori-connect-calendar opens one Google consent screen for read-only access, then saves the refresh token and the account name in .env. Production reads them from Secret Manager.
  • The refresh token stays on the worker.
  • calendar_read covers the primary calendar and up to 9 others selected in Google Calendar.
  • If the account isn't connected or Google refuses the token, the tool returns available: false and the task says so. An OAuth app in Google's testing state loses its refresh token after 7 days.

The capability catalog

The worker adds a short catalog to the inner loop's instructions, with today's date in the configured time zone. Each entry gives the capability's tools, account and availability, what to do on failure, and how to confirm a result.

  • A missing credential leaves the tool in place, and the tool reports itself unavailable.
  • Each search charges the task's budget $0.005, Brave's listed price on Oct 31, 2026.
