Control tools are safe to repeat. Dynamic tools from connected MCP servers or provider adapters run through the same invoke executor, with MCP tools defaulting to unknown effect so they require an approval or explicit allow rule.

Confirming a change

Every tool call is recorded as an operation before dispatch and verified through provider evidence or a follow-up read.

Action classHow the change is handled
Read (read)Allowed when connected; output is saved and citable as evidence.
Reversible write (reversible_write)Checked against permission rules; operation records the action digest and provider confirmation.
Sensitive send / unknown (sensitive_send, unknown)Requires an action-digest-bound approval or explicit matching allow rule before dispatch. Uncertain outcomes are never retried automatically.
Image inspection, batch limits and search pricing
  • A single model turn may propose at most 64 tool calls; the entire batch is validated before any call runs.
  • upload_inspect sends one attached image and one question to the task model in a separate call with no tools. Only the text answer joins the task's history, so text inside an image cannot invoke a tool. Its cost counts against the task's budget.
  • Each web_search call adds $0.005 to the task's spent total; without BRAVE_SEARCH_API_KEY, web search reports itself unavailable.
  • compose scripts run every step through core/internal/permissions and pin every call to its extension digest; on worker restart, completed steps are reused and finished writes are never repeated.
