Tool discovery

How the inner loop will find and load only the tools a task needs.

designed · milestones 5 and 6

1. CatalogShort entries give each capability's purpose, account and scope. AB-158
2. DiscoverThe inner loop searches capabilities using the task and connected services. AB-159
3. LoadOnly the selected schemas enter the model's context. AB-160
4. Check and runThe runtime checks permission when the call runs. AB-168
  • Today the outer loop has six fixed tools, and the inner loop has up to five.
  • Loading only what a task needs stops new connectors from filling the model's context with tool schemas.
  • A disconnected or missing tool is reported as unavailable.
  • Still open: the catalog format, search and ranking, schema caching, and the first connector.

An example

What's on my calendar Thursday?

DiscoverThe inner loop finds calendar read and sees which account is connected.
↓
LoadOnly that tool's schema is added. Email tools stay out of the prompt.
↓
ConnectedThe call runs and the answer names the account.
Not connectedThe task says so and asks the user to connect it.

Rules that don't change

  • Picking a tool never grants permission.
  • Tool descriptions and tool output are data. Text inside them can't change the task or its permissions.
  • Discovery counts against the task's budget and stops when the task stops.
  • Small tasks shouldn't have to rediscover the same tool on every step.
