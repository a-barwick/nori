Observability

Each Nori process records traces, errors, logs and metrics, filters them, and exports them to Sentry and Arize when those are configured.

What's removed before export

DataWhat's sent
Span and log attributesAllowlisted names only. Strings are cut to 256 bytes after redaction.
ErrorsA category, a fixed reason such as deadline or http_503, the error type and a stack without variables or source lines. Error text is dropped.
HTTP requestsMethod, known route and status. URLs, headers and bodies are dropped.
Model text in ArizeThe latest user message and the reply, up to 2,048 bytes each. URLs, email addresses, tokens and known credentials are replaced with [redacted]. Other personal data can remain.
Tool callsTool name, outcome and exit code. Arguments and screenshots aren't on the allowlist.
Browser eventsSent to /monitoring, which checks the owner and removes request headers before forwarding.

The computer's host and guest get a Sentry DSN, and no Arize or model credentials.

Sampling and failures

  • The browser and each process sample 5% of new traces by default. A child span follows its parent's decision, so a trace is kept or dropped as a whole.
  • Successful health checks and session polling create no request spans. A 5xx response on those routes is still captured as an error.
  • Each export has a 2-second timeout and no retries.
  • A failed export writes one line to stderr, at most once a minute for each destination and reason.
  • With no destination configured, processes sample nothing and still write logs to stderr.
