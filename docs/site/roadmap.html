Roadmap

Twelve milestones, showing what is built and what remains.

MilestoneCapabilityImplementation
1Simpler and cheaperBuilt. Pause, idle computer stop, task budgets and a billing alert.
2Conversational homeBuilt. Saved chat, message batching and debug traces.
3Many tasks at onceBuilt. Independent tasks, separate browser pages, steering and task events.
4Waits and finishing properlyBuilt. Durable questions, tool error handling and record checks before completion.
5Real capabilitiesBuilt. Search, long shell jobs, image reading and calendar reads.
6Approvals and writesBuilt. Exact calendar and email approvals, saved outcomes and provider checks after a lost response.
7SubtasksBuilt. Linked work, a shared budget and Stop across parent and subtasks.
8Results and filesBuilt. Saved results, revisions, uploads, typed messages and an event stream.
9Schedules and monitorsBuilt. Reminders, later and repeating tasks, monitors, and email when the app is closed.
10Memory and contextBuilt. Saved memory and summaries reach both loops, long task requests are shortened, and tools load by capability.
11Proactive assistanceBuilt. The calendar check offers help with events too close to drive between.
12More clientsPlanned. Native apps, sign-in, devices, push and shared read positions.

Built means implemented. It does not mean every acceptance scenario has passed. The 116 written conversations define behavior to check.

What remains

  • The billing alert has verified a nonzero provider report. Delivery after crossing the spend threshold remains unverified.
  • Closed-app notifications go out by email only. Browser and native push remain planned. The web client lists schedules with pause, resume and cancel controls.

Following one request

“Check Saturday's weather in Tucson” starts a task. “No, Phoenix” changes its instructions. The result stays saved after a disconnect.

“Please remember that I prefer evenings” changes saved memory without starting a task. “Remind me tomorrow at 10 am to stretch” saves a schedule, and the reminder arrives at that time.

Completion and approval boundaries

Completion checks saved instructions, tool results and evidence references. The outer model compares the proposed answer with cited results. There is no Jev completeness check.

Calendar writes and email sends require approval. Shell and browser calls have no approval step. Standing permissions are not implemented.

Remaining defects and unrun scenarios stay open separately from implemented capabilities. An implementation label makes no claim about the current deployed revision.
