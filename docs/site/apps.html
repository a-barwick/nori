Registry

Every tool, built in or contributed, is a definition with a stable id, a model-facing name, its input schema, a binding to the code that runs it, and a policy: effect, where it runs, retry behaviour and timeout. A digest covers everything that changes what a call does. The model name must match ^[A-Za-z0-9_-]{1,64}$; built-in names cannot be claimed by packages.

When the task model asks for a tool, the activity resolves the definition and records it with the call in the workflow history. The workflow itself never looks anything up in the registry, so a history replays with the definition it was recorded with even after a package changes. Calls recorded before pinning existed still replay through the old name-based policy.

Connections

A connection is one account at one provider: its identity, the scopes granted, the resources the user selected (for example two calendars), its health, and a revision. Several accounts per integration are allowed. Which account Nori uses by default for a purpose, such as creating events, is a user preference rather than a property of the connection.

StepWhat happens
ConnectReturns a one-time sign-in attempt bound to the user and the integration, with PKCE and state. Only the scopes for the requested purposes are asked for.
CallbackFound by state within the signed-in user only. A cancelled or replayed callback creates nothing new. The browser returns to a path inside the web app.
UseThe executor asks Connections for a client for exactly one account. A failed write is never retried on another account.
DisconnectCloses new calls first, then revokes at the provider. Saved results keep their source as a copy.

Health is one of ready, needs sign-in, needs more access, revoked, rate limited, temporarily failing, provider unavailable or credential store unavailable, each with a repair action.

Where account credentials are kept in production is not decided yet. Local development uses an encrypted file store that refuses to run outside the local cloud setting.

Google

Calendar list, events, free/busy, create, update, cancel and respond; ICS preview and import; Gmail search, read, drafts and send; contacts lookup. Event creation uses an id derived from the action, so a retry after a lost response finds the event instead of creating a second one, and an uncertain write is read back before anyone is asked.

Outlook and Microsoft 365, iCloud, HEY, Drive, OneDrive, Dropbox, Notion, Linear, GitHub, Slack and Teams have no connector yet.

MCP

Remote MCP servers over Streamable HTTP, added by the user or by a package. Discovery runs outside the workflow; each discovered tool becomes a definition named mcp/<server>/<tool> with its own digest. A server's tool annotations are advisory, so MCP tools are treated as effect unknown and need an approval or an allow rule. A token for a server is written once and never returned.

MCP sign-in with OAuth, managed stdio servers, resources, prompts and interactive requests are not built.

Nori also answers MCP at POST /mcp for the user's own external clients. Each client gets a token shown once, scoped to read or to read and change; changes keep their request ids, so a retried submit returns the same task.

Plugins and skills

A package has a manifest naming what it contributes and the access it needs. Installing a package grants nothing on its own. An update that asks for more access is refused until the user approves it; the review shows tools, schemas and access added or removed. Packages can be pinned, rolled back and removed; history from removed packages stays readable.

A skill is saved instructions with inputs and the tools it expects. Editing a skill makes a new version. Skills carry no account access.

Executable package tools run on the computer in a sandbox with memory, process and CPU limits, separate user, network, mount and IPC namespaces, and a deadline. If the computer cannot provide that isolation, the call fails and says so. A failure inside the sandbox (deadline, memory limit, nonzero exit) is recorded as failed and does not block later calls.

Package hooks run in the same sandbox, only for the package's own tools, within a deadline (2 seconds by default, at most 10). A pre-invocation hook can refuse a call but cannot change approved arguments; a result hook can reshape what the model sees while the recorded outcome stays as it was.

Context, progress and task-lifecycle hooks are not supported yet.
