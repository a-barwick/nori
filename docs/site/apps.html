Extension registry

Every tool—built-in or contributed by an MCP server or connection adapter—is registered as a versioned extensions.Definition with a stable ID, model-facing name, JSON Schema input, execution binding and policy (effect class, location, retry behavior and timeout). A content digest covers everything that affects what a call does. Model names must match ^[A-Za-z0-9_-]{1,64}$, and built-in names are reserved.

When a task proposes a tool call, the runner resolves the definition and pins it with its digest on the saved OperationRecord. Approvals, evidence checks and crash recovery always bind to that pinned digest even after an MCP server updates its schema.

MCP tool bus

Nori connects to enterprise tools and the host app's MCP gateway via core/internal/connectors/mcp. Users or hosts manage servers through /v1/mcp:

  • Remote Streamable HTTP servers: Discovery runs on connect/refresh outside active tool execution; each discovered tool becomes a definition named mcp/<server>/<tool> whose version hashes its description and input schema. Outbound URLs pass through core/internal/netguard egress checks to block private/metadata SSRF targets in hosted environments.
  • Local stdio servers (development only): When NORI_CLOUD=local, servers can bind to an allowlisted command_ref declared in NORI_MCP_COMMANDS—API requests never pass raw command lines.
  • Untrusted annotations by default: A remote server's tool annotations are treated as advisory, so discovered MCP tools default to effect unknown and require an approval card or explicit allow rule.
  • Resources and prompts: When an MCP server exposes resources or prompts, Nori adds read-only protocol tools (list/read resources, list/get prompts).
  • Write-once credentials: Bearer tokens or OAuth client credentials are stored in Postgres via envelope-encrypted secret/rowstore and are never returned by API reads.
  • Interactive input: If an MCP server requests user input mid-call, Nori cancels the blocking call and hands a durable question to the task so the user can answer without holding an open connection.

Provider-agnostic connections port

core/internal/connections provides the clean port for account lifecycles (connections.Integration interface, OAuth PKCE/state flow, Grant tracking, resource selection, health projections, disconnect/revocation and user preferences) behind /v1/integrations and /v1/connections.

StepWhat the port enforces
Connect & callbackOAuth start returns a one-time PKCE + state attempt bound to the signed-in user and integration; replayed or cancelled callbacks create nothing.
Credential storageCredentials live in Postgres via core/internal/secret/rowstore (envelope-encrypted with a 32-byte key or AWS Secrets Manager); raw secrets are never returned over the API.
Scoped useThe executor requests credentials for exactly one connection ID. A failed write is never retried on another account.
Health & disconnectTracks ready, needs_sign_in, needs_more_access, revoked, rate_limited, temporarily_failing, provider_unavailable or credential_store_unavailable. Disconnect closes new calls before revoking.

The private Google Workspace beta exposes Google Calendar, user-selected Drive files, and Gmail sending to designated testers. Enterprise deployments plug in internal tools through MCP servers or custom adapters implementing connections.Integration and invoke.Adapter. Nori routes its built-in self-management tools through the same permission checks.

Scripts of tool calls (compose)

When a step needs many calls whose results are combined, the task model can send one compose script instead of calling tools one at a time. A script is versioned JSON supporting ordered steps, list iteration with filters, references to earlier results and an output template (up to 64 calls total, at most 8 concurrent).

Every call inside a script is an ordinary recorded operation with its own permission check, approval and digest pin. The script sees tool results, never credentials. On worker restart, finished calls are reused and completed writes are never sent again; if a call requires user approval, the script pauses on that interaction and resumes once answered.
