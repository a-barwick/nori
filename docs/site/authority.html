Approvals and writes

Nori can read freely. Before it changes a calendar or sends an email, the user approves the exact action.

Move my dentist appointment to Friday at 2pm.

Inner loopCalls the move tool with the event's ID and the new time.
↓ proposed move
RuntimeReads the event, saves the exact action and makes the task wait.
↓ the action to approve
UserSees the account, calendar, event, old time and new time.
↓ approve or decline
Runtime, if approvedUses the approval once and sends the saved action to Google.
Runtime, if declinedRecords the decline and refuses the same action again.
↓ the write's result, or the decline
Outer loopCompares the answer with those results and reports what is done.

The write tools

A write made by a subtask asks the user for its own approval.

ToolStops a duplicateConfirms the change
calendar_createThe event ID comes from the exact action, and the runtime looks it up first.Reads the event back.
calendar_moveA repeat finds the approval used and only reads the event. An event already at the new time needs no write.Reads the new time back.
email_sendThe message carries an ID from the exact action in its own header, and the runtime checks recent sent mail first.Reads the sent message back.

What an approval covers

  • An approval covers one saved action and can be used once. The runtime sends the saved action and ignores any later model output.
  • A correction voids the approval, including a correction sent after the user approved. The task then proposes again.
  • It survives waits and restarts while no correction has arrived, and it has no timer.
  • A restart or a repeated delivery can't use it twice.

What can't grant permission

  • A label from the Jev classifier or a task category.
  • A tool being available.
  • Text in a web page, email, document or tool result.
  • A task's own summary of its next step.
  • A turn started by a task event.

Recording what happened

Prepared→Attempted→Confirmed
  • A write can also end as submitted, declined, voided, failed or uncertain, and uncertain is never shown as success.
  • “Did you add it?” is answered from this record.
  • A write that has started finishes first, even after Stop, and Nori reports it.

When a response is lost

Add lunch with Jamie tomorrow at noon.

Google saved the event, but its response never arrived. The runtime then reads the event by its ID and finds it. Nori replies that the lunch is on the calendar and creates no second event.

  • After a worker dies during a write, the next worker checks with the provider and doesn't send again.
  • If the provider can't be read, the task asks the user.

What this doesn't cover

  • Shell commands and the computer's browser have no approval step, because the runtime can't tell what a command changes. The Google token stays off the computer.
  • Standing permissions aren't built, so every write asks.
Limits and outcomes
  • The calendar tools can't add attendees, and they send no notifications.
  • A move is refused on an event with other attendees, because the change would move their copies too.
  • Writes go to one configured calendar.
  • A move is refused if the event changed after the user saw it, and a write is refused if its start time has passed.
  • One transaction checks for new corrections and marks the approval used.
  • A chat approval needs a turn started by the user's message, with a word of assent such as "yes" or "send" in it.
  • An email missing from the latest 10 sent messages stays uncertain, unless the account has fewer than 10 sent messages.
  • A send is refused if the connected account or write calendar changed after the approval.
OutcomeWhat it means
PreparedThe action is saved and waits for the user.
AttemptedThe approval is used, and the provider hasn't answered yet.
SubmittedThe provider accepted it, and a follow-up read didn't complete.
ConfirmedA follow-up read shows the change.
DeclinedThe user refused. Nothing was sent.
VoidedA correction arrived first. Nothing was sent.
FailedThe provider refused the write, a later read shows it didn't happen, or a pause or Stop interrupted it before asking.
UncertainThe runtime couldn't read the provider. It's never shown as success.
