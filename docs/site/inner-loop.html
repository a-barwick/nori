Inner loop

One loop per task: call the model, run the tools it asks for, save the results, repeat.

Each task gets one workflow (nori-task-v3).

  • The workflow body in task/workflow.go contains only deterministic transitions.
  • Every model call, tool call and Firestore write is an activity with its own timeout.
  • Signals (task-command) only wake the workflow. It then reads commands from Firestore by position and incorporates each one exactly once.

Failure handling in milestone 4

OutcomeBehavior
A tool returns a failureThe task receives the saved result and can ask for direction. The saved question includes any accompanying explanation of the failure.
The task failsReport the failure and recorded operations. Wait for the user; do not re-issue it automatically.
A write has an uncertain outcomePreserve the operation record and ask for direction before another attempt.

When a tool fails

A nonzero shell exit reaches the model, while an operation failure preserves its outcome and asks for direction. The broader action policy remains planned beyond milestone 4.designed
