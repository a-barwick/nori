Authentication and typed API contracts

  • Identity mapping: The web BFF verifies OIDC/IAP sessions and resolves verified identities via POST /api/users/resolve. Missing sessions return 401; unprovisioned identities return 403.
  • Service auth: Trusted server proxies attach short-lived HS256 service tokens; iOS authenticates directly with verified Google ID tokens.
  • Strict isolation: Every user-scoped upstream call is prefixed with /users/{id}. Nori scopes Work, interactions, receipts and results to that user and returns 404 for any other user's resource ID.
  • Typed contracts: Clients share the OpenAPI 3.1 spec (api/openapi.yaml) with generated TypeScript types (web/src/lib/contracts/openapi.d.ts) and Go/Swift conformance tests.

For hosted standalone web deployments on AWS, NORI_CLOUD=aws verifies OIDC ID tokens via jose JWKS discovery (NORI_OIDC_ISSUER, NORI_OIDC_AUDIENCE, NORI_OIDC_COOKIE) and resolves the verified issuer and subject to a provisioned Nori user. See core/infrastructure/aws/README.md.
