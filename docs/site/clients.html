Headless the host app integration

integrations/embed/adapter.mjs lets the host app embed Nori without duplicating agent orchestration or state:

  • Identity mapping: the host app supplies verifyIdentity(request) returning { issuer, subject } and a server-side binding table mapping each identity to a distinct provisioned Nori user ID. Missing sessions return 401; unmapped identities return 403.
  • Service auth: the host app supplies serviceAuthorization(signal) returning the Authorization header (HS256 service token in hosted AWS deployments).
  • Strict isolation: The adapter prepends /users/{mappedUser} to every upstream call. Nori scopes Work, interactions, receipts and results to that user and returns 404 for any other user's resource ID.
  • Typed contracts: Clients consume the generated TypeScript types from contracts/assistant/ (web/src/lib/contracts/assistant.ts) for Work items, approval interactions and mutation receipts.

For hosted standalone web deployments on AWS, NORI_CLOUD=aws verifies OIDC ID tokens via jose JWKS discovery (NORI_OIDC_ISSUER, NORI_OIDC_AUDIENCE, NORI_OIDC_COOKIE) and resolves the verified email to a provisioned Nori user. See core/infrastructure/aws/README.md.
