# Nori documentation

Keep pages factual, concise, and useful to someone reading the code for the first time. Use the existing layout and classes. Diagrams and tables are useful when they explain the subject; they are not required for every edit.

Prefer updating an existing page over creating another. Link to source files for implementation details. Distinguish implemented behavior from proposals, and keep private data and credentials out of the public site.

The writing skills and agent map are optional aids. There are no mandatory reviews, screenshot exercises, word counts, punctuation bans, commit trailers, or publication checks. Publish only when requested.
