Outer loop

The part of Nori you talk to. It runs one short turn at a time and hands real work to tasks.

Only one turn owns the conversation at a time. The engine in conversation/runner.go and call.go is built so a process can die at any line and the next owner can recover from checkpoints without sending a second reply or dispatching the same task twice.

Batching rules

ArrivalBehavior
First message, idleTurn starts immediately.
Follow-up mid-turnDrops unpublished output, waits 1s after the latest follow-up, and restarts with all the inputs.
After 3 restartsFinishes the captured batch. Newer inputs wait for the next turn.
Task event mid-turnSaved for the next turn. The current turn carries on.
Panel Answer / StopSkips Jev and the model and goes straight into the same command path.

Classification doesn't grant permission

“Could you check when my domain renews?” has the intent ask, and the model still has to dispatch a task for it. We've also measured Jev over-firing: request_work and provide_input trigger on “Who wrote Hamlet?”, which is why those flags don't rule out the light tier.

Outer-loop tools model.go · taskTools

ToolEffect
dispatch(request)Creates an independent task. Returns once the task is accepted, before it has finished.
steer(run_id, text)Adds instructions to one task. Unrelated constraints stay in place.
answer(run_id, question_id, text)Resolves that specific open question. Stale IDs are rejected.
continue(run_id, question_id)Grants another $1. Only valid for the current budget question, and only when Austin has asked for it.
stop(run_id)Requests cancellation of that task only.
hold(task_id, question)Parks a chat question until that task's result arrives. designed

Only the outer loop dispatches work. An inner loop that needs outside work will ask for it through a control tool, which is designed but not built yet (how the loops talk).

What Jev is looking for

Jev tags each batch of messages with the intents it sees. The model still reads the original words and decides what to do.

One message, several jobs

A single message can answer something, steer a task and start another. It all comes back as reply text plus one tool call per job, in one response.

Like Saturday, should I wear shorts?

  • “Saturday” steers the weather task.
  • The shorts question waits for the forecast.designed
  • The reply answers it once the result arrives.
