Outer loop

The part of Nori that handles the conversation. It runs one short turn at a time and dispatches work to tasks.

One turn owns the conversation. Checkpoints let a replacement process recover the response and accepted commands.

After 3 restartsFinishes the captured batch. Newer inputs wait for the next turn.
Task event mid-turnSaved for the next turn. The current turn carries on.

Classification doesn't grant permission

“Could you check when my domain renews?” has the intent ask, and the model still has to dispatch a task for it.

Outer-loop tools model.go · taskTools

ToolEffect
dispatch(request)Creates an independent task. Returns once the task is accepted, before it has finished.
steer(run_id, text, interrupt)Adds instructions to one task. Unrelated constraints stay in place.
answer(run_id, question_id, text)Resolves that specific open question. Stale IDs are rejected.
continue(run_id, question_id)Grants another $1. Only valid for the current budget question, and only when the user has asked for it.
stop(run_id)Requests cancellation of that task only.
hold(task_id, question)Saves a chat question until that task's result arrives.

Only the outer loop dispatches work. An inner loop that needs outside work will ask for it through a control tool, which is designed but not built yet (how the loops talk).

User turns request schema-constrained output. Intro and task-notification turns still return plain text and cannot issue commands.

Provider behavior and recovery

Sol low replaced Muse after Muse omitted commands and rejected structured responses in local checks. The schema uses the existing command definitions; no second model call forces dispatch.

Rejected responses stay in private attempt records and are excluded from later model history. Recovery reuses accepted command receipts; it does not repeat the model call.

hold(task_id, question) saves a question without changing the task's instructions. A terminal event supplies the outcome for its answer.

When a task ends

The turn that reports a task's end includes the answer, the unmet items and up to 8 KiB of the results the task cited. The outer model compares them and tells the user what is and isn't done. Finishing a task has the rules.

What Jev is looking for

Jev marks which of nine intents are in each batch of user messages. The outer model reads that hint with the original messages. Classifying a message has the intents and the rules.

One message, several jobs

A single message can answer something, steer a task and start another. It all comes back as reply text plus one action per job, in one response.

Like Saturday, should I wear shorts?

  • “Saturday” steers the weather task.
  • The shorts question waits for the forecast.
  • The reply answers it once the result arrives.
