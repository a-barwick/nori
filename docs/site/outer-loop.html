Where task instructions come from

InputRole in the extra call
Current user messagesCan request new work or change an active task.
Earlier user messages and saved identitiesResolve references. They don't repeat an old instruction.
Task output and assistant repliesStay outside the extra model call. If a reference depends only on them, the call may ask for clarification.

When a task ends

The turn that reports a task's end includes:

  • The answer.
  • The unmet items.
  • Up to 8 KiB of the results the task cited.

The outer model compares them and tells the user what is and isn't done. See Finishing a task.

Batching rules

ArrivalBehavior
First message, idleThe turn starts immediately.
Follow-up during a turnDrops unpublished output, waits 1 second after the latest follow-up, and restarts with all the inputs.
After 3 restartsFinishes the captured batch. Newer inputs wait for the next turn.
Task event during a turnSaved for the next turn. The current turn carries on.
Task panel answer or Stop buttonSkips Jev and the model, and goes straight into the same command path.

One message, several jobs

A single message can answer something, steer a task and start another. The reply text and one action per job come back in one response.

Make that Sunday. Should I wear shorts?

  • “Sunday” steers the weather task.
  • The shorts question waits for the forecast.
  • The reply answers it once the result arrives.
Provider behavior, recovery and response goals
  • The default outer model is gpt-6.2-sol at low reasoning effort, through the OpenAI platform API. All three are settings.
  • When untrusted task output is present, side-effecting tool calls (dispatch, steer, answer, stop, hold, remember, forget) add one call to the same model.
  • That call receives user messages, runtime task metadata, saved-result IDs and non-task-derived Core memories. It excludes task prose, earlier command arguments, assistant replies, summaries and filenames.
  • The runtime replaces the proposed command arguments with this call's arguments and validates memory writes. Missing user source records, context over 128 KiB or a failed call prevent commands.
  • Intro and task-notification turns return plain text and can't issue commands. A task's work request with no user message can only dispatch a subtask or answer it.
  • If a response has actions without text, the runtime writes an acknowledgment.
  • Rejected responses stay in private attempt records. Recovery reuses accepted command receipts and doesn't repeat the model call.
  • hold(task_id, question) saves a question without changing the task's instructions.
