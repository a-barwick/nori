Who can reach it

Google IAP plus an exact owner email check. Signed-out requests and forged owner headers are rejected.

Request-driven workers

A worker runs as a bounded slice per Cloud Tasks wake, on authenticated Cloud Run services. Older worker pools stay at zero.

Pausing

What pause doesBlocks new execution, scales workers to zero and stops the computer.
What keeps workingThe website, chat, saved history and any waiting tasks. Nothing is cancelled.

Releases

  • CI/CD is off. When requested, make deploy releases the latest main from the owner's Mac and leaves Nori paused until make unpause.
  • Worker builds are immutable and pinned, so running tasks stay on code that's compatible with them.
  • core/infrastructure/release/ holds the release and smoke test scripts.

Seeing what happened

  • Debug view: each reply shows its recorded model, hint, latency and cost.
  • Sentry: operational errors and traces, without request bodies or prompts.
  • Arize: AI spans as metadata. Saving redacted content requires an explicit setting.
  • Both exporters are optional and can't block a request if they fail.

Trial evidence for the computer
  • A file, an installed package, a browser cookie and local storage all survived a guest restart and a move to a new host.
  • This covers graceful restarts. RAM, live tabs and sudden crashes aren't covered.
  • The disk has no backup yet: AB-189.
Network and credential checks

These are checks from the October 2026 trials. They don't establish production hardening.

  • The computer has public IPv4 egress through host NAT, and guest IPv6 is off.
  • Guest attempts to reach cloud metadata and host SSH were rejected.
  • Chromium's debugging port binds to guest loopback, and host SSH accepts only IAP's source range.
  • The GCE host has no service account.
  • Credentials stay in a gitignored mode-600 .env, or in Secret Manager for hosted services. They're kept out of images, logs, model context and workflow history.
