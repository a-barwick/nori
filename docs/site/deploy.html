Who can reach it

Google IAP plus an exact owner email check. Signed-out requests and forged owner headers are rejected.

Request-driven workers

A wake is a Cloud Tasks request that starts a process. Each wake runs a worker for a limited slice of time, on authenticated Cloud Run services.

Pausing

  • Pause blocks new execution, scales workers to zero and stops the computer.
  • The website, chat, saved history and waiting tasks keep working. Nothing is cancelled.

Releases

  • CI/CD is off. When requested, make deploy releases the latest code from the owner's Mac and leaves Nori paused until make unpause.
  • Worker builds are immutable and pinned, so running tasks stay on code that's compatible with them.
  • core/infrastructure/release/ holds the release and smoke test scripts.

Backups

  • Production's Firestore records and the computer's data disk get a daily copy, kept for seven days. The boot disk and sandbox have no scheduled copies.
  • Restores go into a new database or a new disk, never over the live ones.
  • On October 31, 2026, restored Firestore collection counts matched the export, and a disk restored from the snapshot reached ready state. Files inside the restored disk weren't checked.

Spend alerts

GCP budget alerts don't cap Temporal, so a separate daily check alerts on Temporal spend. Budgets and controls lists the model call limits, and Observability covers traces.

Computer trials and options

These are checks from the October 2026 trials. They don't establish production hardening.

  • A file, an installed package, a browser cookie and local storage all survived a guest restart and a move to a new host. RAM, live tabs and sudden crashes aren't covered.
  • The computer has public IPv4 egress through host NAT, and guest IPv6 is off.
  • Guest attempts to reach cloud metadata and host SSH were rejected.
  • Chromium's debugging port binds to guest loopback, and host SSH accepts only IAP's source range.
  • The GCE host's service account can only read release objects.
