Deployment

Production runs one distroless static Go binary (cmd/nori --role=all|api|worker) on Cloud Run, with Postgres and Google Cloud Storage. Local development runs Postgres in Docker Compose.

Authentication boundary

Hosted deployments verify OIDC ID tokens (NORI_OIDC_ISSUER, NORI_OIDC_AUDIENCE) or the host app's verified session at the host layer, resolve the user, and call the Go API with 1-minute HS256 service tokens (nori-service). Only /healthz and /readyz are unauthenticated.

Graceful drain & split roles

Run --role=api and --role=worker separately to scale horizontally. On SIGTERM, workers stop claiming new leases, drain in-flight runners up to 25 seconds to a checkpoint boundary, and release leases immediately for another replica.

Secrets and credentials

  • On Cloud Run, the service account authenticates to Cloud Storage and Cloud KMS. With NORI_CLOUD=aws, the AWS SDK uses workload IAM roles and stores files in S3.
  • Postgres stores per-user MCP and connection credentials with envelope encryption (core/internal/secret/rowstore). Cloud KMS (NORI_CREDENTIAL_KMS_KEY) or a 32-byte key from NORI_CREDENTIAL_KEY wraps each data key. With NORI_CLOUD=aws, NORI_CREDENTIAL_KEY_SECRET reads that key from AWS Secrets Manager.
  • Stored files stay private under user-scoped artifacts/ prefixes. Writes are conditional and refuse to overwrite an existing object.

Container images and rolling deploys

  • After CI passes on a main commit, it builds the nori-core and nori-web images and tags them with that commit.
  • The Release workflow runs every three hours and on demand. It picks the newest main commit with passing CI and releases only the services whose code changed since the live revision.
  • A release runs migrations, deploys each new revision with no traffic, and moves traffic to it after its health probe passes. A 5xx or crash from a new revision in the next ten minutes moves its services back to their previous revisions.
  • scripts/release.sh rollback core|web|all moves services back to their previous revisions by hand.
  • core/infrastructure/Dockerfile builds the static CGO_ENABLED=0 nori binary onto gcr.io/distroless/static-debian12:nonroot.
  • Inner tasks checkpoint state and receipts in Postgres, so a new binary resumes parked tasks without pinned workflow build IDs.
  • docs/Dockerfile and docs/deploy.sh package the static Dokyu output into an unprivileged nginx container serving X-Robots-Tag: noindex and Disallow: /.

Pausing and operations

  • Execution pause blocks new task admission while the conversation thread, saved history and waiting tasks stay readable. Nothing is cancelled.
  • Each worker pod runs a 60-second repair sweep reconciling nori_task_leases and nori_user_wakes against nori_records, replacing any separate reconciliation CLI.
  • nori-user provisions and manages user rows in Postgres.
  • The repository contains no Terraform. Cloud resources are created with gcloud.
