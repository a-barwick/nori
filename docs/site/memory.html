Memory and context

Each loop gets a small starting context and looks up more only when it would change the next decision.

Outer loop sees

  • Up to 24 recent turns, capped at 192KiB
  • New messages
  • Each task's status and open question
  • Jev's hint

It never gets worker transcripts or the inner loop's tools.

Inner loop sees

  • The request
  • Later instructions, word for word and in order
  • Its own tool calls and results

The plan adds source references and lookups on demand.

That's what runs today. The rest of this page is the plan for milestone 10.

Five kinds of memory

KindHoldsExample
User knowledgePreferences, people, recurring constraints“Remember I prefer evenings.”
Conversation historyWhat was said and decided“What did we decide about Tom?”
Active workOpen tasks, blockers, commitments“What's still running?”
ProceduresWays of doing recurring work“Do it this way next time.”
AuthorityPermissions and approvalsKept apart, so a remembered preference never acts as permission.

How far does a correction reach?

Thursday this time. Applies to this task only.

Remember I prefer evenings. A saved preference.

Do it this way next time. Could mean several things, so Nori shows what it would save first.

What every memory carries

  • Where it came from, and whether the user said it or Nori inferred it.
  • How widely it applies.
  • A way to inspect, correct and forget it.

A forget request reports exactly what was deleted. Removing a preference doesn't erase old messages.

Keeping context small

  • Large tool output lives outside the prompt, with a short summary and a reference.
  • Compaction keeps constraints, corrections, open questions and links back to the originals.
  • Saved history is never deleted to save context.
  • Tool discovery uses the same budget.

Still open
