Saving and forgetting

The user saysWhat the runtime saves
“Please remember that I like my coffee decaf after lunch.”A new memory, with the message it came from.
“i eat fish now btw. still no other meat. update that for next time”The vegetarian memory is overwritten with “eats fish but no other meat”.
“Forget my old home address.”That memory is deleted. Earlier chat messages still contain the address, and the reply says so.
“My partner really doesn't like spicy food.”Nothing. A preference is saved only when the user asks.
  • The outer model proposes each change, and the runtime saves it with the published reply, so a restart saves it once.
  • A memory never counts as permission. Approvals still need the user's own yes in the current message.

Summarizing older turns

  • After a reply, with no message waiting, the runtime checks the turns after the summary.
  • When there are more than 8, or they pass 16 KiB, the inner loop's model adds up to 24 older turns to the summary. The newest 4 stay out.
  • Each summary item quotes the user's own words. The runtime drops any quote it can't find in the message the item names.
  • Stored turns and messages don't change. Only what the model sees gets shorter.

What the inner loop sees

A task sees its request, later instructions in order, and its own tool calls and results. It doesn't see saved memories or the summary.
