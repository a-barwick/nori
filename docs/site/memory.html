Memory and context

Each outer reply is built from saved memory and recent turns, and background jobs save durable facts to memory before older turns leave the prompt.

Three-tier memory model

Core Memory

Facts, preferences, people and projects. Unpinned items over 24 KiB move to today's Daily Log.

Daily Logs

Session decisions, flushed notes, demoted Core items and task outcomes. Up to 64 KiB and 128 entries per date, then a new shard.

Working Memory

A gist and up to 80 summary items, each with a quote from the user's message. Up to 16 KiB.

  • A memory never grants tool permissions. Every Core item and Daily Log entry has a provenance: user_explicit, pre_compact_flush, summary_evicted, task_outcome or dream_curated.
  • A finished task adds a task_outcome note of up to 600 bytes to today's Daily Log in the same Publish transaction. It never changes Core Memory.
  • A remember or forget call commits in the same transaction as the reply, so a retry applies it once and a superseded reply applies nothing.
  • If one user turn mixes dispatch or steer with remember or forget, planUserCommands plans all four tools from the user's messages only.

Coupled pre-compaction flush & AutoDream

Three background passes run after a reply is sent. Each one stops when the user sends a new message.

PassStarts whenSaves
Compaction (flush_and_compact)Unflushed turns reach 16 user turns, 28 turns or 48 KiB. The newest 14 turns stay verbatim.Core upserts, Daily Log notes and a new Working Memory summary, in one serializable transaction. Summary items over the limit move to the log as summary_evicted.
Extraction (flush_and_compact with extract_only)6 user turns have not been extracted, or 10 minutes pass after the latest turn.Core upserts and Daily Log notes only. It writes no summary and leaves the recent turns as they are.
AutoDream (dream_consolidate)15 minutes idle, at least 12 hours since the last run, and at least 10 user Daily Log entries since then. The consolidate action on POST /v1/memory/actions starts it by hand.Merges duplicates, replaces superseded facts and moves stale unpinned Core items to the log. It never promotes task_outcome entries.
  • Every saved Core item and note must be backed by a user's input ID or quote.
  • A failed compaction retries after 2 minutes, then after 5. After the third failure, Nori saves the user's text to the Daily Log and moves on.
