Decisions

Architectural decisions shaping Nori as the persistent, multi-user assistant engine inside a host app.

The loops

Subtasks

DecisionWhyRejectedDate
A parent task parks on request_work, and subtask outcomes deliver back in the same transaction that saves them.Applies the parent-waits-for-children pattern over the existing outbox with no extra model call on delivery.Relaying every subtask result through an outer turn, Temporal child workflows or separate Pub/Sub.Oct 25
The parent owns the budget, and stopping or steering a parent stops its subtasks.Splitting work cannot reset spending, and stale subtasks stop wasting budget.Separate budgets per subtask or letting orphaned subtasks finish.Nov 1
A turn with only a work request can dispatch for that request or answer it, and nothing else.Untrusted task text cannot approve, stop or steer unrelated tasks.Letting work-request turns invoke every outer tool.Nov 1
One request starts up to 4 subtasks in one response, and subtasks cannot nest further.Results arrive together, and single-level nesting keeps Stop and shared budgets simple.Unlimited subtask nesting.Nov 1

Permissions, ports and MCP

DecisionWhyRejectedDate
Deny-wins permission rules with explicit selectors (tools, connections, resources, action classes, recipients, automation/goal scope). Empty selectors match nothing.Makes standing authority auditable and prevents accidental broad grants.Implicit allow-on-connect or coarse global toggles.Nov 11
Every approval card binds an exact action_digest (a SHA-256 hash), task revision and interaction revision.A steer supersedes pending approvals; changing any argument invalidates the digest and forces a fresh approval.Approving by tool name alone or silently executing modified arguments.Nov 11
Remote MCP tool annotations are advisory; discovered MCP tools default to effect unknown and require approval or an explicit allow rule.An external server cannot self-declare a destructive tool as a safe read.Trusting server-supplied read-only hints without policy checks.Nov 11
Pin every tool call to its extensions.Definition content digest on its saved OperationRecord.Approvals, evidence checks and crash recovery stay bound to the exact tool schema even after an MCP server updates its description.Re-reading live mutable registry schemas when validating or recovering calls.Nov 11
Guard outbound remote MCP HTTP requests with core/internal/netguard and restrict stdio MCP commands to allowlisted NORI_MCP_COMMANDS in local dev only.Prevents SSRF against cloud metadata or internal networks and prevents arbitrary command execution via API requests.Unrestricted outbound URLs or arbitrary shell command lines in MCP config.Nov 11

Finishing and budgets

DecisionWhyRejectedDate
The model proposes complete, the runtime verifies records and cited evidence, and the outer loop compares the answer against cited tool outputs.Deterministic record checks avoid flaky LLM-judge scores while catching unsupported claims.A Jev verdict threshold or trusting tool-free completion claims.Nov 1
Each top-level task starts with a $1 default spending ceiling (NORI_TASK_BUDGET_USD). Reaching it stops the task incomplete with saved work; continuation starts a linked new task from Work.Keeps task lifetimes bounded and explicit without an interactive continue budget-question loop inside the task runner.Fixed step counters or repeated in-task budget-grant prompts.Nov 11
Direct OpenAI tariffs price cached input tokens at 1/20th of uncached input; missing or unpriced model cost is recorded with a cost_status of unknown, without failing a valid response.Matches actual provider billing and avoids discarding completed work when usage fields are absent or routed through a gateway.Failing every task on unknown cost or ignoring cached token discounts.Nov 11
Retries follow each tool's action class: reads may retry, writes and uncertain operations never repeat automatically.Prevents duplicate external side effects after lost responses.Retrying entire model/tool activities blindly.Oct 25

Results, memory and context

DecisionWhyRejectedDate
Each message, task, result or read-position change appends a numbered log event in the same Postgres transaction.Sequence numbers follow commit order, preventing missed or out-of-order SSE frames.Timestamp ordering or polling full snapshots every 2 seconds.Nov 2
Editing a saved result always creates a new version; competing revisions keep the first completed version current and preserve the other with a conflict notice.History stays intact and no work is silently overwritten.In-place overwrites or automatic merging.Nov 4
Three-tier memory (Curated Core, Daily Log, Working Memory) combines explicit remember/forget with decoupled session-idle extraction, AutoDream consolidation and quote-verified compaction.Captures useful context automatically without blocking replies while keeping every tier inspectable, editable and grounded in source quotes.Blocking turns on extraction, unverified LLM summaries or opaque vector-only memory.Nov 22
Outer turns target 96 KiB of reply context, and a model request over 192 KiB is refused. Long inner transcripts replace older tool outputs with retrievable operation IDs past 128 KiB.Preserves call/result pairing and provider prompt-cache prefixes without rewriting saved history.LLM-rewritten task history summaries or unbounded context windows.Nov 3
Attached images are inspected via a separate no-tools model call (upload_inspect); SVG uploads are refused.Images are not resent every turn, text inside images cannot call tools, and SVG scripts cannot execute.Embedding raw images in every turn or previewing arbitrary active content.Nov 2

Infrastructure, clients and contracts

DecisionWhyRejectedDate
Serve first-party web, macOS and iOS clients through one Go API behind OIDC/IAP auth and per-user /users/{id} scoping.One backend engine owns conversation, tasks, permissions and receipts across every client.Duplicating orchestration across clients or maintaining an unused standalone embed proxy.Nov 26
Target GCP or AWS with Postgres and object storage (GCS or S3), from one binary (cmd/nori --role=all|api|worker, Secrets Manager or Cloud KMS, OIDC and HS256 service auth, distroless static Go image).Unifies outer and inner durability on Postgres with minimal operational footprint and identical local/AWS behavior.Operating Temporal Cloud or self-hosted Temporal alongside SQS wake consumers.Nov 22
Commit task commands, checkpoints and discovery rows (nori_task_leases, nori_user_wakes) in the same Postgres transactions with LISTEN nori_wake hints.Eliminates cross-service split-brain and replay ceremony while guaranteeing crash recovery via document-fenced leases (ConversationControl, TaskControl).Maintaining a separate workflow engine and outbox relay.Nov 22
Automations deliver to the in-app inbox (in_app) only; external notification channels stay outside Nori.Keeps scheduler delivery deterministic and lets the host app own enterprise notification channels.Bundling personal SMTP or Web Push relays inside Nori core.Nov 21
Enforce API compatibility via OpenAPI 3.1 (api/openapi.yaml) with openapi-typescript, Go kin-openapi handler validation and iOS conformance tests.Catches schema drift across Go, TypeScript and Swift in CI without hand-rolled schema compilers or fixture boilerplate.Hand-rolled JSON Schema codegen and unverified client DTOs.Nov 26

Models

DecisionWhyRejectedDate
Provider, model and reasoning effort are settings for each loop. The OpenAI defaults are gpt-6.2-sol for the outer loop and gpt-6.1-luna for the inner loop, which uses the Responses API. Providers are BYOK (OpenAI, Anthropic, Google, Vercel AI Gateway, OpenRouter) or paired Home AI connectors. The optional classifier is jev-latest.The outer loop returns structured actions, and the inner loop replays provider-neutral Responses.Tying workflow history to a vendor-specific SDK.Nov 11
