Task transcript

Each task saves its messages, tool calls and tool results, and one adapter turns them into a model request.

Task activitiesAppend messages, tool calls and results. They import no provider package.
↓ transcript, tool list and output limit
Model contractRespond makes one request. Inspect asks one question about an image.
↓ Responses request
OpenRouter adapterSets the price ceiling, reserves spend and reads the cost.

An example

For the request "What is the title of example.org?", the transcript holds the saved turns below. The model asks for a page, receives it, and proposes an answer.

RoleParts
userText: the request.
modelProvider state, then a browser_navigate call.
userThe result of that call, with the page title and an evidence reference.
modelProvider state, then a complete call with the answer.

Saved form
Transcript typeSaved JSON
Message{"parts": [...], "role": "user" | "model"}
Text{"text": "..."}
Tool call{"functionCall": {"id": "...", "args": {...}, "name": "..."}}
Tool result{"functionResponse": {"id": "...", "name": "...", "response": {...}}}
Provider state{"thought": true, "thoughtSignature": "..."}, where the signature is base64 of nori.responses: followed by the output items OpenRouter returned.

The field names come from the Gemini SDK, which the transcript used before it had its own types. Keeping them means blocks saved earlier still read, and a worker built before this change can read new blocks.

Blocks from the Gemini period also hold thought text and binary signatures. They read without error, and the model is never sent those parts.

Provider state is replayed only by the adapter that wrote it. Any other adapter rebuilds the turn from its text, tool calls and tool results.
