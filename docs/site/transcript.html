Task transcript

Each task saves its messages, tool calls and tool results in Postgres, and one Responses adapter turns them into a model request.

PostgresHolds the transcript as private history blocks alongside TaskControl checkpoints.
↓ transcript
Task activitiesLoad the transcript, shorten a long one, and call the model.
↓ instructions, transcript, selected tools and output limit
Responses adapterBuilds the Responses request, meters usage and calculates or reads cost.
↓ Responses request (OpenAI, OpenRouter, or gateway)
Model providerReturns the turn, its tool calls, token usage and optional cost.
↺ activities append the turn and each tool result to the transcript in Postgres

An example

For the request “Pull the Q3 revenue summary”, the transcript holds the saved turns below.

RoleParts
userText: the request.
modelProvider state, then an MCP or web_search call.
userThe result of that call, with its output and operation evidence reference.
modelProvider state, then a complete call with the answer and cited evidence.

Provider state is what the model provider returned for a turn, such as encrypted reasoning and call IDs. Nori keeps it exactly so the turn can be replayed.

Long tasks

  • Once a transcript passes 64 KiB, the activities replace the output of each older tool result of 512 bytes or more with a short stub. The stub holds the operation ID and outcome. The newest 32 KiB of messages stays unchanged.
  • The saved transcript keeps every result. The model reads a replaced output again with operation_read.
  • If the request is still over 128 KiB, the activities archive older rounds behind a history reference. The model reads them with task_history_read.
  • Replacement moves forward only when the transcript passes 64 KiB again. Until then each request starts with the same prefix as the last, so the provider's prompt cache still applies.
Saved form
Transcript typeSaved JSON
Message{"parts": [...], "role": "user" | "model"}
Text{"text": "..."}
Tool call{"tool_call": {"id": "...", "name": "...", "args": {...}}}
Tool result{"tool_result": {"id": "...", "name": "...", "response": {...}}}
Provider state{"provider": {"format": "...", "data": "<base64>"}}, where format is nori.responses (OpenRouter), nori.openai.responses (direct OpenAI) or nori.gateway.responses (gateway).

core/internal/task/history.go marshals transcript.Message directly so saved transcript blocks stay provider-neutral and replay cleanly across worker builds.

The Responses adapter (core/internal/agent/responses/) targets direct OpenAI, OpenRouter or a deployment-owned model gateway (core/internal/modelgateway/). It replays a turn verbatim when it carries provider state the adapter wrote, and rebuilds other turns from their text, tool calls and tool results.
