Task transcript

Each task saves its messages, tool calls and tool results in Postgres, and one Responses adapter turns them into a model request.

PostgresHolds the transcript as private history blocks alongside TaskControl checkpoints.
↓ transcript
Task activitiesLoad the transcript, shorten a long one, and call the model.
↓ instructions, transcript, selected tools and output limit
Responses adapterBuilds the Responses request, meters usage and calculates or reads cost.
↓ Responses request (OpenAI, OpenRouter, or gateway)
Model providerReturns the turn, its tool calls, token usage and optional cost.
↺ activities append the turn and each tool result to the transcript in Postgres

An example

For the request “Pull the Q3 revenue summary”, the transcript holds the saved turns below. The model invokes a tool, receives its output, and proposes an answer. Provider state is what the model provider returned for a turn, such as encrypted reasoning and call IDs, kept exactly so it can be replayed.

RoleParts
userText: the request.
modelProvider state, then an MCP or web_search call.
userThe result of that call, with its output and operation evidence reference.
modelProvider state, then a complete call with the answer and cited evidence.

Long tasks

  • Once a transcript passes 128 KiB, the activities replace the outputs of its oldest tool results with their operation ID and outcome. They stop when the newest 64 KiB of messages is left unchanged.
  • The saved transcript keeps every result. The model reads a replaced output again with operation_read or inspects older blocks with task_history_read.
  • Replacement starts again only when the request passes 128 KiB again. Until then each request starts with the same prefix as the last, so the provider's prompt cache still applies (cached input tokens on direct OpenAI tariffs cost 1/20th of uncached input).
Saved form

The task activities import no provider SDK.

Transcript typeSaved JSON
Message{"parts": [...], "role": "user" | "model"}
Text{"text": "..."}
Tool call{"functionCall": {"id": "...", "args": {...}, "name": "..."}}
Tool result{"functionResponse": {"id": "...", "name": "...", "response": {...}}}
Provider state{"thought": true, "thoughtSignature": "..."}, where the signature is base64 of nori.responses: followed by the output items the Responses API returned.

The field names stay compatible with historical transcript blocks so retained task histories read and replay cleanly across worker builds.

The Responses adapter (core/internal/agent/responses/) targets direct OpenAI (gpt-6.1-terra), OpenRouter (openai/gpt-6.1-terra) or a deployment-owned model gateway (core/internal/modelgateway/). It replays a turn verbatim when it carries provider state the adapter wrote, and rebuilds other turns from their text, tool calls and tool results.
