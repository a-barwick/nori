Service API

The host app and the test workbench send user-scoped HTTP requests to Nori and follow saved state through snapshots and resumable SSE streams.

Client / the host app UISends a message or approval decision with a client-generated UUID.
↓ same-origin request
The host app adapter or workbench serverVerifies user identity, prefixes /users/{id} and attaches an HS256 service token.
↓ authenticated HTTP request
Agent service (nori)Validates strict JSON contracts, commits to Postgres and enqueues wakes.
↓ snapshot, mutation receipt or numbered SSE frame
Client / the host app UIMerges saved state by ID and tracks the event cursor position.

Complete /v1/* route families

All user-scoped routes sit under /users/{id}/... (resolved by the host via POST /api/users/resolve or the host app's binding table). Only GET /healthz and GET /readyz are unauthenticated. Every mutating /v1/* management endpoint uses the idempotent envelope { request_id, expected_revision, value } and returns a saved MutationReceipt.

Reusing a message or mutation request_id with identical content replays the saved outcome; reusing an ID with different content returns HTTP 409 (idempotency_conflict). Optimistic revision mismatches return HTTP 409 (revision_conflict) with the current resource payload.

The event stream

The assistant SSE stream (GET /v1/conversations/assistant/events) emits unnamed server-sent events with { seq, kind, conversation, messages, ... } where the SSE id equals seq. Start from the snapshot's position and reconnect with ?after=N or Last-Event-ID. Streams end cleanly after 150 seconds so proxies stay under request timeouts; clients reconnect from the last applied seq.

Event kinds include message, conversation, task, result, operation and read_position. Payloads carry current upserts resolved by the server so hosts do not need N+1 follow-up fetches. On kind: "reset" (or any sequence gap), close the stream, fetch a fresh snapshot and resume from its position. Heartbeats are SSE comments and do not advance the cursor.

Cancelling the assistant turn via POST /v1/conversations/assistant/cancel fences the active reply so a late model response cannot publish or dispatch commands, while already-accepted background tasks continue independently until stopped through Work.

Optional runtime feature flags

Both feature flags default to true. Set a flag to false to disable it; any other non-empty value is rejected at startup.

SettingEffect when false
NORI_BACKGROUND_TASKS_ENABLEDDisables assistant background task routes (returning HTTP 501 with code: "not_enabled") and drops Jev and inner-task key requirements at startup.
NORI_JEV_ENABLEDSkips Jev intent classification and removes the JEV_API_KEY requirement. The outer model, two-call prompt-injection provenance guard and command validation remain active.

Shared read positions

  • The client reports a reply via POST /api/seen only when it enters the visible viewport.
  • Postgres commits the read position and its log event together; older reports cannot move the mark backward.
  • Other open sessions for the same user receive the updated read mark over the SSE stream.
