Route and payload reference

These are the user-scoped agent-service paths. The Next.js server resolves the verified email through POST /api/users/resolve, then prefixes these paths with /users/<id>/ using its own credentials. Browser headers, JSON and query parameters never choose the user. Files and event cursors share the same user scope.

Chats have no conversation-length limit. The model receives the newest complete message groups that fit within 32 messages and 96 KiB of encoded history, stopping at the first group that would exceed either bound. Older messages are omitted, not summarized; saved history is unchanged. Current-turn tool results are separately bounded to eight steps and 16 KiB per result. No new model or shared memory is involved.

Firestore stores each message separately, with a 256 KiB encoded-message ceiling; individual user inputs, model output and tool results also have their own bounds. Events carry at most one changed message. Existing inline chat history migrates atomically on its next update. Reads, duplicate-input checks and write recovery retain access to older records. Unresolved writes stay indexed until recovery records their outcome. A stream reset reloads the latest page; older history can be loaded again.

Assistant messages continue through their existing route. New-chat message routes do not accept the reserved assistant ID.

An open reply or a reused message ID with different content returns HTTP 409 with a message the client can show.

The event stream

StreamSaved eventClient behavior
AssistantNames a changed record and its event number.Merges the record by ID. An unusable cursor triggers a reset and snapshot reload.
ChatContains the chat's title and state, the messages that changed and a consecutive sequence number.Replaces each changed message by ID. Resumes after the stream ends at 150 seconds. A reset or a gap reloads the snapshot.

Repeating a message ID does not create a second turn. Different text or attachments with that ID are rejected.

Stopping a chat preserves partial text. Attempted external actions keep their recorded outcomes.

Shared read positions

  • The assistant client reports a reply only when it enters the visible conversation viewport.
  • The service saves that read position and its event together. Older reports cannot move it backward.
  • Other assistant sessions receive the mark. Independent chat does not report shared read positions.
