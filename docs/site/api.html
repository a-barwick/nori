Complete /v1/* route families

All user-scoped routes sit under /users/{id}/.... The host resolves the ID through POST /api/users/resolve or the host app's binding table.

Only GET /healthz and GET /readyz are unauthenticated. Every mutating /v1/* management endpoint takes the envelope { request_id, expected_revision, value } and returns a saved MutationReceipt.

Reusing a message or mutation request_id with identical content replays the saved outcome.

Reusing an ID with different content returns HTTP 409 (idempotency_conflict). A revision mismatch returns HTTP 409 (revision_conflict) with the current resource payload.

The event stream

The assistant stream (GET /v1/conversations/assistant/events) sends unnamed server-sent events shaped { seq, kind, conversation, messages, ... }. The SSE id equals seq.

  • Start from the snapshot's position. Reconnect with ?after=N or Last-Event-ID.
  • Streams end after 150 seconds so proxies stay under request timeouts. Clients reconnect from the last applied seq.
  • Event kinds include message, conversation, task, result, operation and read_position.
  • On kind: "reset" or any sequence gap, close the stream, fetch a fresh snapshot and resume from its position.
  • Heartbeats are SSE comments and leave the cursor unchanged.
  • A cancel through POST /v1/conversations/assistant/cancel fences the active reply, so a late model response cannot publish or dispatch commands. Accepted background tasks continue until stopped through Work.

Optional runtime feature flags

Background tasks are on unless NORI_BACKGROUND_TASKS_ENABLED is false, and Jev is on only when NORI_JEV_ENABLED is true. Startup rejects other values.

SettingEffect when off
NORI_BACKGROUND_TASKS_ENABLEDAssistant routes return HTTP 501 with code: "not_enabled", and startup drops the Jev and inner-task key requirements.
NORI_JEV_ENABLEDSkips Jev classification and drops the JEV_API_KEY requirement. The outer model, provenance guard and command validation stay active.

Shared read positions

  • The client reports a reply via POST /api/seen only when it enters the visible viewport.
  • Postgres commits the read position and its log event together. Older reports cannot move the mark backward.
  • Other open sessions for the same user receive the updated read mark over the SSE stream.
