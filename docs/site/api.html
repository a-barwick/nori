Service API

Clients send messages and task commands to the agent service over HTTP, and follow saved log events on a stream.

Endpoints

EndpointWhat it does
GET /v1/snapshotReturns the conversation, tasks, results, shared read position and event log position.
GET /v1/eventsStreams saved log events after a position.
POST /api/sessionReturns the same snapshot for older callers.
POST /api/turnSends a message with any attached file IDs. Returns 202 once it's saved.
POST /api/commandSends a task command, such as an answer or a continue.
POST /api/inputSends an explicit update to one task.
POST /api/cancelRequests Stop for one task.
POST /api/traceReads the debug steps for one task.
POST /api/artifactReads a saved screenshot.
POST /v1/uploads, GET /v1/uploads/{id}Saves one attached file, and reads it back.
GET /v1/results/{id}, GET /v1/results/{id}/fileReads a saved result, and its file.
POST /api/seenRecords the newest reply shown in a client and returns the shared read position.
POST /api/deliveredRecords that a browser showed these results.
POST /api/processCloud Tasks calls this to process saved messages. Clients don't call it.
POST /api/resumeRedelivers saved commands and wakes tasks. Clients don't call it.

The web client calls through its Next.js server. See Live updates.

The event stream

RuntimeSaves “Check Saturday's weather in Tucson” and a numbered log event together.
↓ log event number and record ID
Event streamReads the record's current state and sends it.
↓ message, task, result, conversation or read position
ClientMerges the record by ID and remembers the last number.
CaseWhat happens
A reconnectThe client sends its last number as Last-Event-ID or after. The agent service's host drops that header, so the web server passes it in the URL.
A position it can't resumeUnusable, ahead of the log, or over 1,000 log events behind. The stream sends reset, and the client reads a new snapshot.
A long streamEnds after 150 seconds, inside the web service's 180-second limit, and the browser reconnects.
Changes with no log eventEvery 20 seconds, the stream also checks the conversation state and open tasks, and wakes processing for a saved message.

Shared read positions

CaseWhat happens
A reply is shownThe client sends its message ID. The service advances the saved read position and adds a log event in the same transaction.
Another session connectsIts snapshot includes the shared mark. The event stream carries later changes.
An older report arrivesThe saved mark stays unchanged. Repeated reports add no event.

Reading the Tucson weather reply in one web session clears its new-message count in another. See Live updates for viewport reporting.

The mark also suppresses closed-app emails. Its event number lets clients discard older responses.
