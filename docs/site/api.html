Service API

Clients send messages to the agent service and restore saved state through snapshots and event streams.

ClientSends “Total the parts in this CSV” with a message ID and assigned files.
↓ same-origin request
Next.js serverChecks the owner, origin and route before adding server credentials.
↓ validated HTTP request
Agent serviceSaves input before accepting it and publishes recorded changes.
↓ snapshot or numbered event
ClientShows saved state and remembers the event position.

Route and payload reference

These are agent-service paths. The browser reaches them through its Next.js server.

RouteRequest or response
GET /v1/capabilitiesReturns the contract identifier nori-chat-2 and execution-mode metadata.
GET /v1/conversationsReturns {conversations: [{id, title, mode, activeTurn, updatedAt}]}, newest first, without messages.
POST /v1/conversationsAccepts {title?} and returns the new chat.
GET /v1/conversations/{id}Returns a chat snapshot. Reserved ID assistant returns the existing assistant session.
DELETE /v1/conversations/{id}Deletes an idle chat with its events, upload records and files.
POST /v1/conversations/{id}/messagesAccepts {id, text, attachments?: [uploadID]}. Returns {turnId, conversation} with HTTP 202.
POST /v1/conversations/{id}/cancelAccepts {turnId}.
POST /v1/conversations/{id}/approvalsAccepts {questionId, decision}, with approve or decline.
GET /v1/conversations/{id}/events?after=NStreams {seq, kind, conversation, messages}. conversation has no messages, and messages holds only those the save changed. Kind reset asks the client to reload the snapshot.
POST /v1/conversations/{id}/uploads?id=UUID&filename=NAMEAccepts raw file bytes. GET /v1/conversations/{id}/uploads/{uploadID} reads them.
POST /api/turnAssistant input: {id, message, attachments?}. Returns HTTP 202 after saving and confirming wake delivery.
GET /v1/snapshot, GET /v1/eventsAssistant session and record-change stream. POST /api/session remains available.
POST /api/command, /api/input, /api/cancelAssistant task commands, updates and Stop.
POST /v1/uploads, GET /v1/uploads/{id}Assistant file upload and download.
GET /v1/results/{id}, GET /v1/results/{id}/fileSaved results and file bytes.
POST /api/seen, /api/deliveredAssistant read position and result-delivery reports.
POST /api/trace, /api/artifactTask debug steps and screenshots.
POST /api/process, /api/resumeInternal processing and task delivery. Browser clients cannot call these through the proxy.

Assistant messages continue through their existing route. New-chat message routes do not accept the reserved assistant ID.

A full chat, a pending approval, an open reply and a reused message ID with different content each return HTTP 409 with a message the client can show.

The event stream

StreamSaved eventClient behavior
AssistantNames a changed record and its event number.Merges the record by ID. An unusable cursor triggers a reset and snapshot reload.
ChatContains the chat's title and state, the messages that changed and a consecutive sequence number.Replaces each changed message by ID. Resumes after the stream ends at 150 seconds. A reset or a gap reloads the snapshot.

Repeating a message ID does not create a second turn. Different text or attachments with that ID are rejected.

Stopping a chat preserves partial text. Attempted external actions keep their recorded outcomes.

Shared read positions

  • The assistant client reports a reply only when it enters the visible conversation viewport.
  • The service saves that read position and its event together. Older reports cannot move it backward.
  • Other assistant sessions receive the mark. Independent chat does not report shared read positions.

Reading the Tucson weather reply clears its count in another assistant session. See Live updates.
