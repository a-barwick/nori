## Decisions D1–D4 (decided by the coordinator on 2026-11-09)

The coordinator set these as working defaults on 2026-11-09, choosing the recommendation with the strongest engineering evidence from the three reviews, after misreading a complaint about permission dialogs as a request to stop consulting Austin. They are the coordinator's calls, not Austin's; he can overturn any of them with a word, and every mechanism stays configurable.

| ID | Decision | Why | Mechanism |
| --- | --- | --- | --- |
| D1 | Connected-account credentials live as envelope-encrypted rows in the existing database: a per-record data key wrapped by a master key, the master key from the deployment's key service in production and from a local key file in development. The local file vault remains the development store until the row store lands. | Backend's reasoning held up in review: refresh compare-and-swap, authorization epoch and disconnect must be atomic with the connection row, a secret store cannot add versions conditionally and so needs a pointer row anyway, and the design works the same on Postgres and Firestore. Integration judged it the option with fewer failure modes to prove. Cost: key management and ciphertext in backups. | Backend implements the row store behind the existing credential interface, with the master key resolved through the secret boundary; no production deployment is part of this work. |
| D2 | A direct explicit request authorizes the action it names. An automation holds exactly the standing authority its creation preview showed, materialized as permission rules, and unattended runs proceed within that grant; expanded access or a materially changed action returns to the user. | This is the plan's accepted text and r0's recommendation; the interim confirm-writes default would have made every unattended automation interactive and defeated A25, A30 and A44. | `NORI_USER_SENDS=allow` (landed at `18d6e3b`); `NORI_AUTOMATION_UNATTENDED` defaults to `require_rule`, and the creation preview shows the exact rules. |
| D3 | Creation defaults: read and summary runs catch up the latest missed occurrence; reminders deliver only inside their execution window; unattended writes and sends expire outside their window; missed and expired occurrences show in history with a reason. `missed_run` stays required and editable per definition. | r0's recommendation; replaying every missed occurrence produces stale messages and bursts of changes. | The creation screen preselects these per trigger kind and says so in plain words. |
| D4 | Disconnect keeps deliberately saved Library items and action history, closes access immediately, revokes remotely where the provider allows, purges transient caches, and offers a separate explicit deletion of imported content. Saved items show copied provenance and the source's disconnected state. | r0's recommendation, supported by all three streams. | `purge_cache` defaults to true and `delete_imported_content` to false on disconnect; the dialog offers the deletion unchecked. |
